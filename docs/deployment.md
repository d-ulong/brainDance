# 部署与运行方案

## 1. 环境与地域

首期生产采用中国大陆单区域云的托管运行环境、托管 PostgreSQL 和独立 Worker；具体供应商以后续 ADR 决定。development 与 staging 只使用合成数据，隔离数据库、密钥和对象存储，禁止复制生产家庭、正文、媒体或完整备份。生产首发为管理员邀请码封闭测试，不开放公开注册或可被索引的注册页。

单区域是 MVP 的有意识取舍：先降低运维复杂度，接受区域级不可用风险；达到下述容量或 SLO 目标后评估跨可用区数据库、Worker 冗余和灾备区域。

## 2. 容量假设与资源边界

| 档位 | 活跃家庭 | 设计假设 | 触发动作 |
| --- | ---: | --- | --- |
| 起步 | 100 | 低并发、每日批处理可在 15 分钟内完成 | 托管单实例 DB + 单 Worker 组 |
| 扩展 | 1,000 | 晚间计划完成和训练提交出现明显峰值 | 连接池、Worker 并发、慢查询预算和只读投影优化 |
| 规模 | 10,000 | 队列、数据库 I/O、导出和审计读取成为独立负载 | 多可用区、分离 Worker 队列、容量压测与灾备评审 |

上线前必须以合成负载确认连接上限、训练提交峰值、日程生成量、18:00 结算量、审计保留增长和导出并发；不得把三档数字当作容量保证。

## 3. 服务目标与告警

- 月度可用性目标：MVP 99.5%；登录、普通读取和训练提交分别监测。
- 计划/积分命令：成功后权威记录立即可读；积分异步结算的 99% 延迟目标在 5 分钟内。
- 撤权：服务端敏感读取立即生效；会话缓存与受限链接的最长有效期不超过 5 分钟。
- RPO ≤24 小时、RTO ≤4 小时；若启用持续日志备份，另记录实际可达到的恢复点，不把技术能力误写成承诺。
- 告警：错误率、慢查询、连接池、outbox 积压、事件租约超时、dead 事件、训练/结算失败、授权拒绝异常、导出/删除失败、对象存储错误和备份演练失败。

## 4. 数据保护与密钥

- PostgreSQL 每日备份并按实际能力配置连续日志；每季度恢复演练同时验证数据库、审计、tombstone 和密钥恢复。
- 删除执行后主存储正文清除；备份最长 90 天轮转清除；无正文安全审计默认保留 3 年，最终期限以合规评审结论为准。
- 密钥只由平台密钥管理注入，按环境隔离和轮换；初始化超级管理员凭据为一次性受控部署配置，首次登录强制 TOTP。
- 日志禁止密码、邀请码明文、训练答案、每日总结正文、下载令牌和媒体链接；审计日志与应用日志分离。
- 对象存储不是 M1–M5 的默认依赖。若 M6 导出或 M7 媒体启用，使用私有桶、生命周期、恶意文件扫描、重编码和短时访问链接。

## 5. 发布、队列与恢复

1. CI 运行类型、静态、单元、集成与端到端检查；staging 使用合成种子数据演练迁移和恢复。
2. 数据库迁移遵循 expand → deploy → contract；训练定义和规则版本只新增。
3. 每个业务事务同步写 outbox。Worker 以租约领取，指数重试；超限进入 dead 并告警，人工重放保留审计。
4. 生产采用灰度或可快速切回的应用发布；回滚不回写历史事实或流水，必要时停止消费者并由权威记录重建投影。
5. 备份恢复后优先应用 deletion tombstone 与授权撤销信息，再恢复普通投影，防止已删除或已撤权内容重新暴露。

## 6. 合规边界

中国大陆部署方向不等于已完成合规。上线前必须完成未成年人、监护同意、个人信息、数据驻留、供应商数据处理协议、数据主体请求和安全事件响应的专业评审。

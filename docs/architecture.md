# 架构设计

## 1. 推荐架构

采用 TypeScript 全栈 Web 系统：响应式 Web 界面、同仓库应用服务、PostgreSQL 和独立 Worker。首版保持一个可部署系统；以深 Module 约束复杂性，而非过早拆分微服务。对象存储仅在 M6 的导出或后续媒体功能实际需要时引入。

```text
浏览器（桌面 / 手机）
  └─ Web 应用：界面、训练交互、表单、可访问性
       └─ 应用服务：身份、授权、领域 Module、查询投影
            ├─ PostgreSQL：权威数据、事务 outbox、审计、投影
            └─ Worker：日程、结算、通知、导出、删除、投影重建
```

推荐技术方向为 Next.js、TypeScript、React、PostgreSQL、SQL 迁移和经验证的会话/身份库。具体库和云供应商在实现 ADR 中决定，业务 Interface 不依赖供应商 SDK。

## 2. Module、Interface 与 Seam

| Module | 对外 Interface | 主要实现责任 |
| --- | --- | --- |
| Identity | 注册、验证、登录、会话撤销、邀请、TOTP | 身份凭据、限流、失败锁定、初始化与换绑 |
| Family Access | 发起/确认/解除关联；读取授权结论 | relationships 权威事实、成员投影、授权纪元、私密授权撤销 |
| Training | 开始、提交、放弃、完成会话；读取训练档案 | 题目、计时、服务端指标、每日有效资格、版本与年龄档 |
| Schedule & Facts | 保存计划、生成实例、变更日程、提交/确认/更正事实 | 计划版本、稳定实例键、Time Policy、事实版本 |
| Settlement & Ledger | 评估事实、读取结算结果/余额、发放手动奖励 | 规则版本、结算幂等、冲销流水、余额投影 |
| Redemption | 申请、取消、批准、拒绝兑换 | 价格快照、月限次、余额锁定、唯一扣减流水 |
| Reflection Privacy | 提交、编辑、删除总结；授予/撤销私密读取 | 可见性、逐家长授权、正文清除与版本审计 |
| Data Lifecycle | 发起/撤销/确认删除；请求导出 | 冻结、tombstone、授权快照、私有一次性下载 |
| Audit & Emergency Access | 写审计；申请、批准和使用紧急访问 | 类型化脱敏审计、重认证、双人审批、短时 capability |
| Notification | 创建、读取、标记站内通知 | 通用文案、去重、未来渠道 Adapter |
| Background Delivery | 发布领域事件；领取/重试/重放任务 | transactional outbox、租约、死信、事件版本 |

每个 Module 的 Interface 同时是测试 Surface。调用者不能直接写投影、余额、授权表、日程事实或 outbox；跨 Module 只传命令、查询结果或版本化领域事件。

## 3. 权限与即时撤权

所有敏感读取在服务端实时核验 active relationship 和资源专用授权；首页、成员和列表投影只缩小查询集合，绝不单独放行。解除关系在一个事务中结束 relationship、更新授权纪元、撤销私密授权、写审计和 outbox。会话与短时媒体链接在读取时验证授权纪元；缓存 TTL 和媒体链接 TTL 必须小于撤权 SLO。

管理员默认不可读家庭私密数据。紧急访问必须重新认证，且由非申请管理员批准；grant 只覆盖精确资源范围和固定短时有效期，每次读取带 grant 标识写审计。

## 4. 数据流与异步可靠性

```text
命令 → Module 事务（权威事实 + audit + outbox）
     → Worker 租约领取 → 幂等处理 → 投影 / 后续命令 / 站内通知
                                      ↘ 重试 → dead + 告警 → 人工重放
```

- 业务事务同步写入 outbox；不得先提交事实、再尽力入队。
- `dedupe_key`、消费者幂等键和源事件版本共同防止重复执行。
- Worker 使用有限租约、指数退避和最大重试次数；超过上限的事件进入 dead，必须告警且保留人工重放路径。
- 日程滚动生成、计划变更重建、18:00 负向结算、通知、导出、删除和投影重建均经过 Background Delivery。
- 投影记录最后处理的源事实/流水；可从权威记录重放。重放不触发新的业务副作用。

## 5. 时间与结算边界

Time Policy 是日程与积分唯一的时间解释处：输入为家庭日期、计划本地时间、事实版本和当前家庭时钟；输出为迟完成状态、奖励资格、更正资格与结算周期。计划日次日 `18:00` 是人工补填正向奖励截止；迟完成窗口截至计划日次日结束；事实更正窗口为计划日后 7 个家庭自然日。三者不得互相推导。

积分调用方只提交已确认事实版本。Settlement 生成唯一结算，Ledger 生成不可变流水；余额只是流水投影。更正以新事实版本、新结算和反向流水完成，不改写历史。

## 6. 响应式、隐私与可访问性

- 移动优先，验收宽度为 360px、768px、1024px、1440px。
- 训练支持触控、鼠标、`Space`/`Enter`、可见焦点和读屏状态；图表有文字摘要，不用颜色作为唯一信息。
- 站内通知使用不含私密正文、积分或计划名称的通用提示；系统级推送延后。
- MVP 每日总结仅文本；AI、语音转写和模型路由不提供 Interface。

## 7. 安全与运行边界

应用日志、审计日志和监控指标分离。日志不得包含密码、邀请码明文、训练答案、总结正文、私有下载令牌或媒体链接。删除请求冻结访问，执行后写 tombstone；备份恢复先重放 tombstone，防止已删正文复现。迁移采用 expand → deploy → contract；规则与训练定义只新增版本。

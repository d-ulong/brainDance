# BrainDance UI 审查与改版建议

审查开始：2026-09-18；报告交付：2026-09-19。状态：**待用户决策，未授权实施**。

基线：`main` / `f87d495a2136b0729aebd14f67ed1317e78f6f1b`。

建议把下一版定位为“清晰、温和的家庭学习工具”：学生端突出当天行动，家长端突出学生上下文与管理效率，训练中突出刺激和作答。保留现有品牌识别，优先重新分配页面空间与视觉重点。

## 审查依据与边界

- 44 张截图：3 张未登录真实页面截图，41 张现有组件搭配浏览器内示例数据的截图。可在 [截图画廊](gallery.html) 中按设备和角色筛选。
- 主覆盖：1440×1000、360×800。补充：768×1024 的双方首页、1024×768 的双方计划页。不是全页面、全尺寸笛卡尔积验收。
- 页面：学生首页、计划、日/周/月日历、训练中心、三种训练说明、反应训练进行态、个人页；家长首页、学生列表、计划列表、个人页；双方计划编辑弹窗。
- 状态：示例有数据、首页无数据、首页读取失败、计划筛选无结果、糖果主题。未做慢网全过程、读屏、缩放和完整浏览器兼容测试。
- 现有 E2E 测试账号尝试登录一次，返回 401；未重试、未创建账号。登录后页面的全部 API 均在浏览器中拦截，不读取真实家庭数据。反应训练的创建/事件响应也是浏览器内模拟，未产生真实训练事实。
- 本报告能确认布局、文案和部分本地交互问题；不能证明真实授权、计时、积分结算和数据加载流程正确。推送详情、兑换、导出、账号删除和真实训练结果/趋势未实拍，后续落地验收仍需补齐。
- 本地无可用生产构建，使用开发预览。截图左下角的 Next.js 开发标识不属于产品 UI。中途开发热重载产生的无效画面已重拍；最终模拟采集正常退出，两个角色的未建模 API 清单均为空。
- 未改动业务代码、数据库或既有规格；未运行迁移、seed、build、全量测试；已有启动脚本修改保留。审查预览已停止。

## 应保留的基础

品牌标志、两套可切换主题、共享页面外壳和基础控件可以继续使用。360px 下主导航已能放下全部学生入口；本轮截图的页面整体宽度均未超过视口。弹窗已有固定标题/关闭区；家庭空状态已经区分创建学生与关联已有学生。这些都不需要推倒重来。

主要不足是：**装饰、概览、导航和操作占据了相近的视觉权重，任务本身出现得太晚；手机布局主要依靠堆叠，尚未充分改变信息呈现方式。**

## 问题清单与具体建议

“高”表示应进入首轮布局/交互方案；“中”表示随公共视觉规范统一。以下均为建议，不是已冻结需求。

### U01 · 高：首页没有把“下一件事”放在中心

**证据：**[学生手机首页](sample-student-home-360.png)、[家长桌面首页](sample-parent-home-1440.png)。学生手机页“现在适合做什么”标题在 y≈692px，“我的训练近况”在 y≈1121px；页面共约1512px高。概览只显示“17:00 · 待完成”，没有直接呈现下一项任务名称。家长首页右栏大面积展示家长自己的训练，家庭信息则在左栏逐个堆叠。

**影响：**打开应用后先读问候和数字，还要寻找任务入口；多孩子家庭的浏览长度继续增长。

**建议：**问候缩为一行；学生首页首屏放“下一项任务：名称、时间、状态、进入日程”，下面显示今日任务列表，再放积分与训练。家长首页先放学生概览和已有待处理事项入口，个人训练放在“我的”中，首页可保留轻量快捷入口。未有可靠数据源的“待处理计数”不得临时编造或靠前端推导权限。

**建议验收：**360×800、有待完成任务时，首屏可见完整任务标题及进入入口；不能仅有统计数或功能卡。空任务时有合适的下一步提示。

### U02 · 高：家长二级导航被截断，页面顶部结构重复

**证据：**[家长学生列表手机](sample-parent-students-360.png)、[家长计划手机](sample-parent-plans-360.png)。二级导航可视宽246px、内容宽368px，“推送/兑换”需要横向滚动发现。“返回”独占右侧空间；不少页面同时存在品牌栏、一级导航、返回栏、标题/工具栏。

**建议：**桌面家长管理使用固定侧栏承载功能分类，内容区顶部只保留当前对象、页面标题和主操作。手机主导航考虑底部固定，二级功能采用可见分组或明确的“更多”，不要把关键入口藏在没有提示的横向区域。必须持续区分“全部学生”“指定学生”“我自己的计划”，不能用界面选择代替服务端授权。

**建议验收：**手机无需猜测横向滑动即可找到所有关键管理入口；任何操作前能辨认作用对象。重新安排导航时保留现有训练离开确认与终止流程。

### U03 · 高：日历占用过多空白，手机周/月视图难以浏览

**证据：**[日视图手机](sample-student-schedule-360.png)、[周视图手机](sample-student-calendar-week-360.png)、[月视图手机](sample-student-calendar-month-360.png)。日视图示例全页约3249px，08:00第一项任务到 y≈1720px才出现。周视图在292px可视区内显示880px内容；月视图内容宽672px，只能先看到部分日期。页面没有整体横向溢出，不代表日历内部可用。

**建议：**手机默认“当天任务列表”，日期条切换日期；周/月用于选择日期和了解分布，选择后展示当天任务。桌面可保留时间网格，但初始定位到当前时间或首项任务，并允许展开完整24小时。任务卡明确写“待完成/进行中/已完成”，不能只靠背景色和操作按钮暗示状态。长标题在详情中必须完整可读。

**建议验收：**手机有任务时首屏至少出现一项；周/月不用横向拖动才能找到今天；凌晨日程仍然可访问。仅改变呈现方式，不丢弃任何时间段或历史记录。

### U04 · 高：计划页卡片过重，操作层级不清

**证据：**[家长计划桌面](sample-parent-plans-1440.png)、[家长计划手机](sample-parent-plans-360.png)、[学生计划手机](sample-student-plans-360.png)。每张家长计划卡包含编辑、预览、复制、添加学生、生成日程五个操作；手机分成两排。筛选区长期全部展开，首张卡在约622px才开始；“新增计划”被挤为两行。学生计划页的概览又占一整块，计划正文约733px才出现。

**建议：**桌面采用紧凑列表/行布局，保留名称、对象、生效信息、生成摘要和一至两个主要操作。手机用紧凑卡片，复制和对象维护归入“更多/管理”，但“生成日程”保持明确入口。搜索保留，其他筛选可折叠并显示已选数量。学生端把积分概览压成一行，计划/日程/目标作为明确的内容切换。

**建议验收：**360px下主按钮文字不被迫断为两行；完整看到首项信息和主要操作不需要先滚过整屏工具；操作收纳后仍可找到全部现有能力。

### U05 · 中：数字表达容易混淆

**证据：**[学生计划页](sample-student-plans-1440.png)。标题“积分余额”下显示“10/120”，实际含义是“今日净积分/余额”；旁边“1/4”才是完成数量的比例。首页对相同余额使用独立数字120。

**建议：**写成“余额 120”“今日 +10”，完成情况写“已完成1项，共4项”，需要时配进度条。正负号、单位、日期格式在全站一致。积分说明放在可访问的详情入口，不依赖悬停。

**建议验收：**不阅读小字也能辨认数字含义；0分、负积分和0项任务不出现歧义。

### U06 · 高：复杂计划编辑不适合长窄弹窗

**证据：**[家长编辑弹窗手机](sample-parent-plan-dialog-360.png)、[桌面](sample-parent-plan-dialog-1440.png)。手机一屏只能到第一项内容的部分字段；优先级、重复、时间限制、多个计分档位在同一长表单中。保存操作在滚动内容底部。

**建议：**计划编辑改为完整编辑页，按“基本信息、任务内容、适用对象”分组；计分和优先级以高级设置展开，保留已有默认值和真实规则。每周重复用星期选择器替代输入逗号数字。固定保存/取消栏，离开未保存内容时给出确认。小型确认和短表单继续使用弹窗。

**建议验收：**手机保存入口持续可达；增加多项任务后仍能辨认当前编辑项；不能因收起高级设置而改变或清空已有参数。不得顺便合并“保存、绑定、生成”的业务事务语义。

### U07 · 高：弹窗视觉阻挡已实现，键盘交互未闭合

**证据：**[键盘实测记录](modal-keyboard.json)。打开家长新增计划弹窗后，焦点仍在背景“新增计划”按钮；将焦点设到弹窗最后按钮后按Tab，焦点离开弹窗到BODY；按Escape后弹窗仍存在。该结果来自现有组件的浏览器实测，和示例业务数据无关。

**建议：**打开时移动焦点到合适位置，Tab/Shift+Tab限制在当前弹窗内，关闭后返回触发控件；为Escape定义关闭或未保存确认行为。背景内容在弹窗打开时不可交互。遵循 [W3C 模态对话框交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

**建议验收：**完整键盘走通打开、编辑、取消和焦点恢复；多层错误/确认弹窗维持正确焦点与层级。

### U08 · 高：空结果与空数据混用，错误缺少就地恢复入口

**证据：**[搜索无结果](sample-parent-filter-no-results-1440.png)。已有3个计划时搜索不匹配的文字，显示0个结果，却提示“还没有计划，点击新增计划”。[首页错误状态](sample-student-home-error-360.png)仅显示错误，训练区提示去其他页重试。

**建议：**分别设计“尚未创建”“没有匹配结果”“加载失败”“暂无权限”。搜索无结果提供清空筛选；读取失败提供当前区域重试；有历史数据时保留并明确标记未刷新状态，不能把旧数据装作新数据。

**建议验收：**搜索不能使用户误以为数据被删除；读失败不显示为0；重试不触发业务重复提交。

### U09 · 高：训练说明与进行态需要不同布局

**证据：**[反应训练进行态](sample-student-reaction-active-360.png)。刺激区从约482px开始，上方仍是完整品牌、换主题、退出、主导航、返回、标题和说明。[Stroop说明](sample-student-stroop-360.png)、[数字广度说明](sample-student-digit-span-360.png)文字密度较高，手机开始按钮靠近或低于首屏。

**建议：**准备页用简短规则、静态示例和难度说明帮助理解；专业名称可配通俗副标题，保留准确术语。进行态使用专注布局：简短标题、紧凑进度、主要刺激区、明确结束入口。训练结束后的数据与趋势另行验证后设计。

**建议验收：**360×800中刺激和必要控制完整可见；减少导航不能省略现有终止确认。色值、刺激时序、作答区域、键盘规则、随机化、年龄档与计分全部按训练规格逐项评估，不能直接跟随主题重着色或默认改难度。

### U10 · 中：视觉语言叠加过多

**证据：**[双方首页与计划截图](gallery.html)同时出现渐变横幅、多色数字卡、彩色emoji、厚底按钮、外层卡片和内层卡片。糖果主题切换后，部分语义块仍使用固定的紫/黄/绿色。后者不必然是缺陷，但目前缺少“哪些颜色随主题、哪些表示状态”的清晰约定。

**建议：**默认采用低饱和背景、清晰正文、一个主要强调色；插图集中于欢迎/空状态/完成反馈。减少多层卡片边框与阴影，用间距和小标题分组。产品图标统一尺寸与笔画，emoji可保留在少量情绪表达处。主题入口移入个人偏好设置，先统一默认主题再校准另一套。

**建议验收：**同一含义的按钮和状态样式一致；颜色不成为唯一状态线索；两套主题分别检查对比度。这里的风格取舍需要用户选择，不能算客观bug。

### U11 · 中：登录页对齐、个人页空白和字体层级需要收敛

**证据：**[登录桌面](login-desktop.png)。标题从x≈176px开始，608px宽的表单从x≈416px开始，标题与操作区不成一组；这不是表单被拉至全屏。[学生个人页](sample-student-account-360.png)只有少量身份信息，却保留240px最小卡片高度。手机主导航文字约10.4px，品牌说明约8.8px。

**建议：**登录标题、账号类型提示与表单同组；个人身份卡随内容撑开。正文以易读为先，辅助文字少量使用较小字号，导航不要通过持续缩小字体解决空间问题。个人页分“学习与成长、账号与家庭、数据与安全”，危险操作不要与高频入口同等强调。

**建议验收：**放大文字后不遮挡、不丢失操作；低龄用户需要阅读的内容不靠小字承载；登录账号类型提示直接可见。

### U12 · 中：样式与文档已经漂移，直接追加覆盖会继续累积不一致

**证据：**`globals.css`中`.bd-top-tabs`、`.bd-library-toolbar`等有多处后续覆盖；`StudentManagementTabs`引用`--bd-primary-soft`和`--bd-ink`，当前全局样式未定义这两个变量；前端组件规范仍写`PageShell max-w-md`，实际外壳为`max-w-6xl`，表单另有限宽。

**建议：**定稿后统一语义颜色、字号、间距、控件高度、圆角和层级；清点实际在用变量，再整理相关覆盖。明确三种页面宽度：窄表单、阅读/详情、宽管理工作台。按最终设计更新规范，保留现有组件体系，不以更换UI库作为本次目标。

**建议验收：**所有引用的设计变量可解析；共享按钮/输入框在页面与portal弹窗中一致；规范与最终实现对应。只整理改版范围内的样式，避免无关重构。

## 建议定稿方向

| 决策 | 推荐方案 | 备选及取舍 |
| --- | --- | --- |
| 整体气质 | 清晰温和，少量探索感；趣味集中在反馈处 | 全面游乐园风更活泼，但会增加复杂管理页的视觉负担 |
| 首页结构 | 学生：今日行动优先；家长：家庭学生优先 | 维持当前欢迎横幅，只调整下方卡片，改动小但首屏问题改善有限 |
| 导航 | 家长桌面侧栏；手机底部主导航；明确对象上下文 | 保留顶部主导航，压缩高度并重排二级入口，结构变化较小 |
| 手机日程 | 默认任务列表，周/月用于选日期和概览 | 保留时间网格并跳到相关时段，能省滚动但仍有宽度压力 |
| 计划编辑 | 独立编辑页，分组+高级设置+固定操作栏 | 保留宽弹窗，增加分组和固定保存栏，桌面可用但手机仍较局促 |

这些决定都尚未生效。确认设计方向也不等于可以跳过关键页面定稿；建议先形成学生首页、家长计划管理、手机日程三个代表页面的高保真稿，再确定公共组件。后续由Codex实施，不交给Cursor。

## 推荐页面内容顺序

| 页面 | 从上到下的信息顺序 |
| --- | --- |
| 学生首页 | 简短问候与日期 → 下一项任务 → 今日任务与进度 → 积分摘要 → 训练/家庭内容入口 |
| 家长首页 | 当前家庭/学生范围 → 学生今日概览 → 已有待处理事项入口 → 计划/内容管理入口 → 个人空间入口 |
| 家长计划 | 当前作用范围与标题 → 搜索及筛选摘要 → 紧凑计划列表 → 明确的编辑/生成入口 |
| 手机日程 | 日期选择 → 今日完成情况 → 任务列表 → 可展开的积分明细；周/月作为辅助视图 |
| 训练进行态 | 简短标题与结束入口 → 当前进度 → 刺激与作答区域 → 必要状态提示 |

## 后续验收边界

布局验收使用相同尺寸、相同示例内容做前后对照；核心操作再用可用测试账号复验。至少包含长标题、0/1/多任务、多孩子、未生成计划、空结果、加载失败、键盘和手机软键盘。训练必须额外核对业务不变量。不能用“页面没有横向滚动”替代组件内部可访问性检查。

建议主要触控操作保持至少44px高度，作为本项目面向儿童的设计目标；不要误写成WCAG AA一律要求44px。WCAG 2.2的目标尺寸最低条款是24×24 CSS px并包含例外，详见[W3C说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。视觉层级依据可参考[NN/g](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)。本轮不宣称已经完成WCAG符合性认证。

## 证据复现

# Brainlab（脑力操练所）网站分析

> 分析对象：[https://aizyd.net/brainlab](https://aizyd.net/brainlab)  
> 取材时间：2026-08-24；以游客状态浏览首页、训练库与个人训练档案。未登录、未提交训练结果，涉及账号、服务端保存与完整排行榜的行为均未做验证。

## 1. 产品定位与核心判断

「脑力操练所」是一个把轻量认知游戏、连续训练和个人进度可视化结合起来的 Web 产品。它并不把自己包装成医学诊断或“提升智商”的承诺工具：页面多次将“脑年龄”定义为娱乐化相对指数，并提示在相近设备和条件下观察个人趋势。[首页](https://aizyd.net/brainlab) 的训练说明也明确了标准评估与自由训练的不同用途。

其体验主张可以概括为：**每天做少量、可完成的认知练习；通过个人历史而非竞技压力感受进步。** 首页用“每天一小课 · 一次只练一课”“继续你的训练线”建立连续性；档案页则直接说明比较对象是“过去的自己”，而不是排行榜。[首页](https://aizyd.net/brainlab)｜[我的训练](https://aizyd.net/brainlab/profile.html)

## 2. 信息架构

全站一级导航稳定地分为五个工作区：

| 一级入口 | 主要职责 | 典型用户问题 |
| --- | --- | --- |
| [首页](https://aizyd.net/brainlab) | 当日决策与状态概览 | 今天该练什么？当前状态是否完整？ |
| [训练库](https://aizyd.net/brainlab/training.html) | 按目标浏览、挑选游戏 | 我想练记忆/专注/推理，该从哪里开始？ |
| [我的训练](https://aizyd.net/brainlab/profile.html) | 进度、最佳成绩、趋势与能力画像 | 我有没有进步、下一步练什么？ |
| [排行榜](https://aizyd.net/brainlab/leaderboard.html) | 社会参照或外部激励 | 我在同类用户中的位置如何？ |
| [认知科普](https://aizyd.net/brainlab/topics.html) | 能力维度与练习解释 | 这些项目在测/练什么？ |

首页承担“任务调度器”角色：首要 CTA 是继续连续训练，次要 CTA 是做标准评估；随后给出三项标准评估卡片和进入训练库的入口。[首页](https://aizyd.net/brainlab) 训练库再把项目按训练意图重新编排，避免用户先理解所有游戏名才能选择。[训练库](https://aizyd.net/brainlab/training.html)

这种结构把产品拆为“选择 → 行动 → 留痕 → 复盘”，导航与内容分层相对一致，没有把所有功能塞进首页。

## 3. 功能模块

### 3.1 标准评估与状态参考

标准评估由三项构成：

- [反应力](https://aizyd.net/brainlab/games/reaction.html)：以中位数毫秒数观察处理速度/准备状态；
- [Stroop 抑制](https://aizyd.net/brainlab/games/stroop.html)：以干扰指数和准确率观察抗干扰表现；
- [工作记忆](https://aizyd.net/brainlab/games/memory.html)：用顺背、倒背数字广度观察短时保持与操作信息的能力。

首页说明用户在近 7 天覆盖三项后，状态参考才更完整；档案页将三项与“脑年龄趋势”绑定，而不是让所有游戏共同改变这一单一分数。[首页](https://aizyd.net/brainlab)｜[我的训练](https://aizyd.net/brainlab/profile.html)

### 3.2 连续训练课程

训练库当前提供“工作记忆 · 7 课循环”：每课 8 次，从上次难度继续，结合顺背和倒背；每天最多推进一课，错过不惩罚。它是典型的低压力习惯机制，避免用户每天面对大而全的训练目录。[训练库](https://aizyd.net/brainlab/training.html)

### 3.3 自由训练库

训练库把 14 个项目按目标组织为四组：

| 目标分组 | 项目 |
| --- | --- |
| 记忆与更新 | 数字广度、N-back、空间记忆（Corsi）、配对联想 |
| 专注与反应 | Stroop 抑制、视觉搜索、速算与持续注意、反应力 |
| 空间与推理 | 心智旋转、图形矩阵、连线切换、密码破译 |
| 规划与挑战 | 规划训练（汉诺塔）、数字找和 |

每张项目卡都配有能力描述和指标语义。例如连线强调完成时间与错误点击，N-back 强调击中、漏报和虚报，规划训练看步数。这种“游戏名 + 练习目的 + 可记录指标”的三层说明有助于降低认知游戏的黑箱感。[训练库](https://aizyd.net/brainlab/training.html)

### 3.4 个人档案与留存机制

[我的训练](https://aizyd.net/brainlab/profile.html) 集中呈现：近 7 天三项标准评估覆盖情况、等级和 XP、各评估最佳成绩、28 天打卡印章、连续课程进度、脑年龄趋势、专项训练雷达图，以及每个游戏的个人最佳记录。

其中数据语义区分明确：连续课程用于推进训练进度；三项核心项目形成状态参考；其余项目服务于自由练习和个人最佳。雷达图覆盖速度、专注、记忆、空间、规划、逻辑和联想等七维，并将“未测”明确显示，避免把缺失数据伪装为低分。[我的训练](https://aizyd.net/brainlab/profile.html)

### 3.5 社会参照与科普

导航保留排行榜和认知科普两个独立入口；首页可见“参考群体/排行榜”方向，而档案页强调自我比较。这样的双轨设计能同时服务希望获得外部反馈的用户与更关注长期自我提升的用户。排行榜、科普页的详情未在本次游客状态中展开验证，因此不对其具体字段或内容量作断言。[排行榜](https://aizyd.net/brainlab/leaderboard.html)｜[认知科普](https://aizyd.net/brainlab/topics.html)

## 4. 关键用户旅程

### 旅程 A：第一次使用 / 建立基线

1. 进入首页，理解“娱乐化自测、非医学诊断”的边界。
2. 选择三项标准评估中的一项或按引导完成状态评估。
3. 评估结果写入个人档案；近 7 天补齐三项后形成更完整的状态趋势。
4. 用户回到首页或档案查看下一项建议。

优势是把最重要的解释与免责声明放在行动前后；待改进点是新用户仍需理解“标准评估、自由训练、连续课程、脑年龄”四个概念的关系，首屏可用一个更短的流程提示进一步降门槛。

### 旅程 B：日常打卡 / 习惯养成

1. 首页直接给出“开始第 N 课/继续训练”。
2. 完成 8 次当前难度的工作记忆练习。
3. 进度与当天训练记录进入档案，打卡印章和课程进度即时可见。
4. 次日继续时从上次难度接续；缺席不会被惩罚。

这个旅程采用“小课、断点续练、无缺席惩罚”的节奏，适合低频但长期的自我训练场景。

### 旅程 C：按目标探索 / 即时娱乐

1. 从训练库选择“记忆与更新”“专注与反应”等目标。
2. 在小组内按描述选择单局游戏，或使用“随便来一局”。
3. 结果沉淀为专项成绩与个人最佳，不改写标准评估趋势。
4. 从档案雷达和项目记录中选择下一次练习方向。

这条路径兼顾“我有明确目标”和“我只想马上玩一局”两种动机。

## 5. 视觉设计系统与交互特点

### 5.1 视觉语言

- **实验纸张感背景**：米白底色叠加浅灰方格，隐喻训练记录、实验表格和长期积累；它为认知训练赋予轻量“实验室”气质，但避免了医疗产品的冷硬感。
- **高对比的排版层级**：深近黑的大号粗体标题、较细的说明文字、短小的橙色眉题，形成明确的“任务—说明—数据”阅读顺序。
- **温暖、克制的配色**：白色/暖灰卡片作为主体，珊瑚橙用于主按钮、当前状态和重点标签，绿色作为课程/正向进度的辅助色。颜色承担状态含义而不大面积铺满界面。
- **圆角卡片与大留白**：首页和档案页以两列卡片收纳概览、打卡与课程；圆角和细边框削弱了数据仪表盘的压迫感。
- **符号化项目识别**：用“ms、色、9、▦、◎、Σ”等简短符号区分游戏，配合文字名称，帮助扫读而不依赖复杂插画。

### 5.2 交互模式

- **双 CTA 层级**：页面把“继续连续训练/开始第 1 课”设为显著主按钮，把状态评估、训练库等设为次级路径，减少用户在首屏的决策成本。[首页](https://aizyd.net/brainlab)
- **渐进披露**：训练库先按目标分类，项目说明再放入可展开区域；用户不必先读完全部术语才开始练习。[训练库](https://aizyd.net/brainlab/training.html)
- **状态可解释**：指标旁带“最佳”“未测”“近 7 天覆盖 0/3”等文本，而非只给图表；脑年龄也持续伴随非医学提示。[我的训练](https://aizyd.net/brainlab/profile.html)
- **有意义的空状态**：没有完整评估时，页面展示尚缺哪些维度和推荐下一项，而不是空白面板。[首页](https://aizyd.net/brainlab)｜[我的训练](https://aizyd.net/brainlab/profile.html)
- **断点续练**：连续课程呈现“下一课、当前轮进度、下一课顺背/倒背长度”，把回访用户直接送回可执行的下一步。[我的训练](https://aizyd.net/brainlab/profile.html)

## 6. 设计优势

1. **动机分层合理**：连续课程解决留存，自由游戏解决探索和即时满足，标准评估解决“我有没有变化”的反馈需求。
2. **指标边界清晰**：把“脑年龄”限制在三项标准评估，把专项成绩保留为独立画像，减少一个总分吞没多维能力的误导。
3. **低羞耻、低惩罚的长期设计**：以自我比较、无缺席惩罚和可恢复进度替代单纯排行榜竞争，适合健康习惯产品。
4. **游戏选择有解释**：按能力目标分组并说明指标，让用户理解“为什么练它”。
5. **数据可视化轻量**：打卡印章、XP、课程进度和雷达图各负责一种反馈，信息密度较高但未完全仪表盘化。

## 7. 风险与可优化点

### 7.1 概念负担仍偏高

新用户会同时遇到连续课程、自由训练、标准评估、脑年龄、专项画像、XP、排行榜。虽然页面已有说明，但可在首页增加一条三步引导：**先做一项标准评估 → 每日完成一课 → 7 天看趋势**；并把自由训练清晰标成“随时玩，不影响脑年龄”。

### 7.2 “脑年龄”措辞的预期管理

即便已标注娱乐化、非医学，"年龄"依然很容易被用户理解为诊断或能力排名。可进一步在首次出现处使用“娱乐化相对指数（脑年龄）”或允许用户切换为“个人状态指数”，并在分享、排行榜附近重复说明其统计边界。

### 7.3 数据存储与跨设备预期

页面文案涉及训练档案、成绩保存和浏览器内记录，但游客状态下未能完整验证其账号、云同步、清缓存和跨设备策略。建议把“哪些数据在本机、哪些数据在服务端、是否需要登录、如何导出/删除”集中写成隐私与数据说明，并在首次训练前链接到该说明。

### 7.4 可访问性与小屏风险

当前桌面端大量使用细线网格、浅灰说明文字、两列大卡片和符号图标。它在视觉上舒适，但应特别检查：

- 浅色辅助文字与背景的对比度；
- 橙/绿等颜色是否有文字或图标冗余编码；
- 移动端卡片堆叠、雷达图文字、28 天印章网格的可读性；
- 游戏本身是否支持键盘操作、可见焦点和足够大的触控目标。

### 7.5 评估质量与可比较性

站点已提醒设备和条件会影响趋势。下一步可在结果页记录/提示影响因素（设备类型、全屏建议、网络/音频要求、练习轮与正式轮区别），并在跨设备或异常波动时降低结论语气。对于反应时尤其重要。

### 7.6 竞争与自我比较的张力

档案页强调不与排行榜比较，导航却保留排行榜。这并非冲突，但建议明确排行榜是“参考/趣味模式”，默认把个人趋势放在更前；榜单页可减少单一总分，增加相近训练时长或分组参照，避免把娱乐指标过度竞赛化。

## 8. 可执行的优先级建议

| 优先级 | 建议 | 预期收益 |
| --- | --- | --- |
| P0 | 首屏增加三步新手路径，并明确三类训练数据的关系 | 降低首次使用理解成本 |
| P0 | 发布明确的数据存储、同步与删除说明 | 建立信任、减少数据预期落差 |
| P1 | 对脑年龄采用更保守的首次文案与分享页提示 | 降低误解与健康类表述风险 |
| P1 | 移动端与无障碍专项验收（对比度、键盘、触控、图表替代文本） | 扩大可用人群 |
| P2 | 根据档案缺失维度给出可解释的下一项推荐理由 | 提升回访与训练闭环 |
| P2 | 为排行榜引入训练时长/分组参照，弱化单一名次 | 平衡趣味与长期动机 |

## 结论

Brainlab 的差异不在于单个脑力小游戏，而在于它把游戏重新组织成一个较完整的“评估—课程—自由练习—档案复盘”系统。其最成熟的部分是对长期训练节奏、个人趋势与非医学边界的表达；下一阶段最值得投入的是首次认知负担、数据透明度、可访问性，以及“脑年龄/排行榜”可能带来的过度解读控制。

## 9. 账户、保存与排行榜补充验证（2026-08-24）

### 9.1 账户与登录：未发现可用登录流程

本次再次在游客状态检查“我的训练”和“排行榜”页面。页面导航统一显示“游客”，页面内没有登录、注册、账户设置或第三方授权入口；公开可见的链接和按钮中也未发现对应功能。因此，当前站点**不能验证登录后的账户资料、跨设备同步、游客数据合并、退出登录、导出或删除账号数据**。这不是“未测试”，而是当前公开界面中未提供可进入的登录流程。

这一点也改变了对产品边界的判断：从当前可见体验看，它更接近“游客即可使用的个人训练工具”，而不是账号体系驱动的训练服务。若站点实际存在未公开的账户体系，应补上清晰入口及数据范围说明；若不存在，则应避免让“档案”“真实玩家”等文案让用户误以为成绩天然可跨设备保存。[我的训练](https://aizyd.net/brainlab/profile.html)｜[排行榜](https://aizyd.net/brainlab/leaderboard.html)

### 9.2 服务端保存：尚不能由用户可见行为证实

游客档案可展示 XP、打卡、课程进度、最佳成绩和趋势等字段，但本次没有创建训练记录，也未发现登录入口；因此无法通过“刷新、重新登录或另一台设备复测”来证明这些数据写入服务端。排行榜页面公开加载了真人成绩，并随页面加载多个与存储、API、榜单相关的客户端模块；但这只能说明站点包含相应实现线索，**不能单独证明游客档案会被服务端持久化**。

报告中的“保存”应据此调整为：游客页面存在训练记录的展示能力；其持久化位置、本地数据清除后的结果、云端同步和失败恢复机制均未证实。建议产品在首次训练前明确告知数据是在本机、会话还是服务器端保存，以及清理浏览器数据、换设备和隐私删除时的结果。

### 9.3 排行榜：已验证的完整可见规则

[排行榜](https://aizyd.net/brainlab/leaderboard.html) 在游客状态即可访问，并提供以下可验证行为：

- 范围可切换为“本周赛、上周结算、历史荣誉、标准挑战总榜”；
- 当前本周赛展示五个项目入口：反应力、Stroop 抑制、工作记忆、轨迹追踪、视觉搜索；
- 当前项目明确给出排序规则，例如反应力为“完整训练、取本周期个人最佳、更低反应时排在前面”；
- 页面公布榜单统计周期和结算时间，例如当前周榜为北京时间 8/24 00:00—8/31 00:00，并在每周一 00:00 结算并开启新榜；
- 用户完成一局同规则挑战后才取得上榜资格，且“是否公开上榜”由用户决定；未完成时会显示进度和“去挑战”入口；
- 榜单定位为自愿参加的真人竞技榜，只展示主动授权的成绩，并声明单局成绩不等于个人能力或真实年龄。

这组规则使排行榜与档案页的“比较过去的自己”形成合理分工：默认是个人训练，公开竞技需要额外完成同规则挑战并作公开选择。仍未验证的部分包括：本人上榜后的昵称/头像、名次更新时机、分页或加载更多、公开选择的具体控件、撤回公开、异常成绩处理与跨设备一致性；这些都需要站点提供登录或可控的测试账号后才能严谨完成。

### 9.4 对原结论的修正

原报告中“账号、云同步和服务端保存”被列为待验证风险，本次验证后应更明确地表述为：**公开游客体验没有可见账号入口；排行榜的公开授权机制可见，但个人训练数据是否服务端保存尚无可验证证据。** 这不是功能缺失的定论，而是当前公开界面没有向用户解释或暴露这些能力。对一款会记录认知训练历史的产品而言，数据归属与可迁移性应成为优先级 P0 的产品说明项。

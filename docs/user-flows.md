# 关键用户流程

所有流程均以登录用户为前提；每个写操作必须在服务端以当前身份和关联状态再次授权。

所有命令必须携带幂等键。每个成功命令在一个事务内写入权威领域事实、审计事件和 outbox 事件；Worker 只处理已提交 outbox。成员、余额、趋势和首页为投影，读取敏感资源时仍以生效关联及资源专用授权实时复核。

关联解除在同一事务中结束授权事实、递增授权纪元、撤销私密授权、记录审计和发布 outbox；成员投影不能单独放行访问。计划实例由计划版本、家庭日期和稳定时间点唯一标识。系统与人工事实均以版本保存；更正创建新事实版本、结算和反向流水，永不覆盖历史。

## 1. 邀请码注册

```text
管理员创建邀请码 → 用户打开注册链接 → 输入邀请码 → 系统校验角色/期限/次数
  → 用户完成账号资料；家长验证手机号或邮箱 → 创建账号并消耗邀请码 → 登录并进入角色首页
```

异常：邀请码无效、角色不匹配、已撤销、已过期或次数耗尽时，创建账户和使用次数都不能发生变化。邀请码不得直接暴露可猜测的连续编号。

邀请码只由管理员创建和撤销；家长不能为学生或其他家长生成邀请码。

### 1.1 5–12 岁学生开户

```text
已注册家长创建受控学生账号并设置登录方式 → 学生首次登录
  → 学生本人阅读关联信息并确认 → 家庭关联生效
```

家长创建账号不等于代替学生确认关联；学生确认仍是阻止误添加的必要步骤。学生账号不得与家长账号共用凭据。

认证方式：家长和管理员使用手机号或邮箱加密码；学生使用用户名加密码。家长必须先完成对应手机号或邮箱验证码验证，未验证账号不能访问学生数据或发起关联。管理员密码验证后必须完成 TOTP；首位超级管理员仅能通过生产环境受控初始化创建，后续管理员由已登录管理员通过邀请码邀请。5–12 岁学生在首次登录时必须把家长设置的初始密码改为自己的密码。

密码重置：5–18 岁学生忘记密码时，任意已关联家长或管理员可发起重置；MVP 不提供学生自助找回。系统使旧会话失效、记录操作者和时间，并令学生下次登录强制修改新初始密码。

### 1.2 13–18 岁学生自主注册

```text
学生使用管理员发放的学生邀请码 → 设置本人登录方式并创建账号 → 首次登录
  → 学生本人确认待处理的家庭关联申请 → 家庭关联生效
```

学生邀请码只能创建学生角色账号；注册不自动授予任何家长访问权。

## 2. 家长与学生匹配

```text
学生本人登录后生成短时一次性关联码/二维码 → 家长扫码或输入关联码并填写最小可见范围
  → 系统校验码、角色、账号和单活跃家庭归属，创建待确认申请并通知学生
  → 学生本人在已登录账号中查看身份与可见范围 → 接受 / 拒绝
  → 接受：建立生效关联；首次关联自动创建家庭，写审计并刷新双方首页
  → 拒绝：申请关闭，不授予任何数据访问权限
```

学生关联码有效 10 分钟、仅可使用一次，学生可随时撤销且同时最多一个有效码；待确认申请在 72 小时后过期，必须用新码重新发起。学生确认是产品内的防误添加步骤，不替代法定监护同意。首位家长创建学生账号或首次关联学生时，必须确认并留存版本化的监护同意和隐私政策；后续加入家长仅确认本人条款。解除关联是即时流程：任意已关联家长或学生发起解除（或管理员基于申诉强制解除）→ 关联立即失效、访问权与私密总结授权立即撤销 → 离关联家长创建的未完成正式计划、积分规则和兑换内容自动停用 → 历史数据保留给原属主，其他家长不能接管配置；全程写审计。重新关联不自动恢复历史私密授权。最后一位家长离开后，学生账号与历史保持可用，学生仍可自主训练、创建和执行个人计划，也可生成关联码邀请新家长加入原家庭；待处理兑换申请自动取消且不扣积分。原创建家长重新关联后，其旧配置仍须逐项手动启用。

## 3. 完成一次脑力训练并沉淀成绩

```text
学生从“今日训练”或训练库选训练 → 按年龄档加载题目与说明 → 阅读用途与非诊断提示 → 开始会话
  → 客户端记录题目、答题与时间；失焦时暂停，累计超 30 秒或恢复失败则 abandoned
  → 服务端校验会话规则并计算指标 → 写入训练会话和指标
  → 当天该项目首条有效完成会话更新个人最佳/近 7 天覆盖/趋势投影并可触发积分；其余标为练习
  → 展示可解释结果与下一步建议
```

关键规则：训练定义必须版本化；前端上报的分数不可直接信任；重放、超时、取消或放弃会话不进入正式统计。反应力以正确反应的中位反应时和准确率计，异常快慢值不进入中位数；Stroop 分别记录一致/不一致试次的准确率和中位反应时，并计算个人干扰差值；数字广度分别记录顺背/倒背最长连续正确位数和每档尝试。训练趋势仅在相同定义版本和年龄档内比较，不形成医学、智力或跨学生排名。家长默认查看聚合结果，需要时可查看详细训练记录，无需学生逐次授权；家长不可修改原始成绩。

## 4. 创建计划、生成日程、标记执行

```text
学生或家长创建目标 → 学生创建的是个人计划（关联家长默认可见但不可编辑）；家长可直接创建正式计划，或将学生个人计划转化为正式计划
  → 正式计划包含频率、一个或多个当天时间点、有效期、负责人，并保留学生个人计划来源 → 日程生成 Module 幂等地产生未来 N 天实例 → 学生在日程中完成/跳过/说明
  → 系统记录状态事件；仅正式计划的合格完成事件投递给积分结算 Module
```

推荐默认值：滚动生成未来 30 天；计划变更只影响未来未完成实例；已经完成或跳过的日程保留其生成时的计划快照。

配置所有权：学生拥有其个人计划；家长可把它转化为由该家长拥有的正式计划，而不是覆盖原始个人计划。正式计划创建者可编辑、停用或删除；其他已关联家长可查看计划，并为既有日程补充执行记录，但不能改变计划规则或其未来实例。

学生可在转化后继续编辑或关闭原始个人计划；已生成的正式计划与其日程保持不变，除非正式计划创建者另行修改。学生或关联家长还可创建不依赖计划的手动日程，但手动日程不触发积分。学生可点击日程“开始”与“完成”记录系统真实时间，也可手动补填开始、结束或耗时；手动事实用于积分时须关联家长确认。家长可为学生设置每家庭自然月的补填次数，默认 5 次；次日 18:00 后录入的事实不产生正向积分。已启用未完成/未达标扣分模板的正式计划，在该时点即使未填报也自动结算扣分。日程完成不要求或支持证明附件。学生或关联家长可在计划日期后 7 个家庭自然日内发起正式事实更正，超期仅管理员基于安全或数据纠错处理。目标只能由其创建者手动完成或关闭，单次日程完成不自动关闭目标。日程跳过原因可选，但跳过不产生正向积分。

## 5. 依据条件规则结算积分

```text
学生将日程标记完成（计划日次日结束前补记则标为迟完成）→ 系统产生完成状态与真实完成时间等系统事实 → 读取适用规则版本 → 评估条件组
  → 生成“结算提案”（命中条件、分值、原因） → 幂等提交积分流水
  → 更新账户余额投影 → 通知学生与关联家长
```

例：事件为“作业日程完成”；事实包含系统记录的完成时间和学生自报的错误数。任意一位已关联家长确认错误数后，它即成为已确认事实。规则依优先级从高到低选择一条，或在明确标记为可叠加时合并。缺少或未确认错误数时，规则必须返回“待人工确认”，不能猜测。

若规则只引用完成状态、系统完成时间等系统事实，则日程标记完成后自动结算；只有规则引用错误数等人工事实时才进入待确认。待确认质量事实不奖不扣，确认后只按当时允许的结果结算。完成但缺少模板要求的时间/质量事实时默认不奖励，只有模板明确字段缺失为未达标条件时才扣分。规则编辑仅作用于之后的新事实，历史结算保留原规则版本。

任意已关联家长可补充或修正日程的完成/跳过状态与人工事实；系统记录操作者。计划日次日 18:00 后的补填只补充档案，不得撤销既有未完成扣分，除非属于系统错误或正式事实更正。若修正改变已自动结算的系统事实，系统以新事实版本创建新结算，并为原结算写反向流水，不得覆盖历史结算；同一事实版本、规则版本和结算周期只能有一条结算，同一规则、日程实例和结算周期的奖扣互斥。

权限：管理员只维护系统模板；家长只能将模板实例化或为已关联学生创建规则；学生只能读取规则、提交任务事实和查看结算结果，不能创建或修改规则。

更正：任意已关联家长可对已确认人工事实发起更正。系统保留原确认、新建更正事实版本与新结算，先以反向流水冲销原结算后再按新事实结算；不得覆盖或删除原事实、原确认或原流水。

### 5.1 积分兑换

```text
家长配置线下兑换内容（名称、积分、说明、启用状态和可选的每学生月限次）→ 学生选择内容并发起兑换申请，固化价格快照
  → 学生可撤销 pending 申请：状态 cancelled，不扣分
  → 任意已关联家长确认 / 拒绝 → 确认：检查余额和月限次，按价格快照写入扣减流水 → 申请完成
                                   → 拒绝：必须填写原因，对学生和所有关联家长可见，不扣减积分
```

可兑换内容由家长配置；学生没有直接扣减余额的 Interface。确认时余额不足或达到月限次必须拒绝，重复确认只能产生一条扣减流水。目录调价只影响新申请，已提交申请按价格快照处理。历史更正导致积分收回时余额可为负；负余额期间禁止新兑换，之后获得积分优先抵消负数。

## 6. 家长推送、学生作答、家长评论（延后，但先固定流程）

```text
任一关联家长选择学生 → 创建文本/链接/图片推送并立即或预约发布；视频嵌入暂不处理；推送默认对学生和所有已关联家长可见，只有创建者可编辑、停用或删除
  → 学生阅读并提交文字、图片或手写图片作答，可多次补充并保留版本；作答默认对所有已关联家长可见
  → 全部关联家长评论、学生回复 → 各评论创建者可编辑/删除自己评论（逻辑删除后家庭仅见“评论已删除”）→ 任务归档
```

媒体上传和评论通知属于独立的授权与审计点。推送与作答图片仅支持 JPG、PNG、WebP，单文件最多 10MB，须经恶意文件扫描和图片重编码；不支持 PDF、压缩包或可执行文件。推送作答默认家庭共享，不提供私密模式；仅支持文本、图片和手写图片，不支持音频、视频或任意文件附件。删除推送/作答后图片立即禁止普通访问，无其他引用的对象文件 90 天后物理清除；外链不抓标题、图片或摘要。视频嵌入与来源治理暂不处理；预约或立即发布只产生站内通用提示，不在 MVP 做任意外链抓取或自动转写。评论编辑版本仅审计、家庭只见最新版本；删除评论后家庭仅见标识，正文仅可经紧急访问读取。创建家长离关联时，未发布预约推送自动取消，重新关联也不恢复；已发布推送、作答和评论保留给仍在家庭中的成员，离关联家长立即失去访问和编辑权。

MVP 每日总结仅支持文本，不支持图片、音频、附件或家长评论；每名学生每家庭日期最多一条，可在当天编辑或删除，家庭成员只看最新正文，旧版本只审计。私密每日总结的可见范围由学生控制：学生可逐一授予或撤销已关联家长访问权，也可主动将总结改为普通总结；改为普通后，所有当前关联家长和后续新关联家长均可访问。普通总结不能改为私密；仍为私密的历史总结不会因新增关联自动开放。学生删除总结后，系统立即撤销所有主体的正文访问并从主存储删除正文，只保留不含正文的删除审计。

每日总结在当前范围内始终由学生自行书写，既不接语音转写，也不送入 AI；未来语音或模型功能将作为独立迭代重新讨论，不沿用本文件的当前流程。

## 7. 共同的流程验收

- 所有写入结果均可刷新后重新读取，且不会因重复请求产生重复数据。
- 每个拒绝结果给出可行动原因，但不泄露他人身份或数据。
- 桌面端与 360px 宽移动端均可完成流程；训练交互提供键盘、触控和可见焦点。

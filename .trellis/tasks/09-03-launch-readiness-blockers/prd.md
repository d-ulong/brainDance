# 上线前阻断项规划

## Goal

将 BrainDance 从 M7 功能完成状态推进到可被组织审查和执行的上线准备状态：把既有上线门槛转化为明确的责任边界、可验证证据、未决外部决策和安全的执行顺序，而不假装技术验证可以替代合规或供应商承诺。

## Confirmed Facts

- M1–M7 已完成；M8 AI/语音明确暂不排期且不得作为下一实现项启动。
- 首期定位为中国大陆、邀请制、5–18 岁、单区域托管 PostgreSQL 与独立 Worker；生产供应商尚未选定。
- 路线图已列为上线阻断项：未成年人数据与监护同意合规评审、隐私政策/同意证据、供应商 DPA 与数据驻留、恢复演练、紧急访问双人审批、容量/SLO 验收。
- 产品和架构已冻结监护同意的版本化审计留存、管理员默认无私密数据访问、紧急访问的重认证/双人批准/限时/审计，以及删除 tombstone 优先于恢复投影。
- 不得把合规评审、供应商能力或容量档位当作已完成的生产保证；development/staging 只能使用合成数据。

## Requirements

- R-LR-01：形成一份可执行的上线门槛清单，为每项列出权威约束、所需证据、责任角色、依赖和不可接受的替代证据。
- R-LR-02：设计恢复演练、容量/SLO 验收与紧急访问流程的可验证方案，明确哪些可在本地/合成 staging 演练，哪些必须由组织或供应商完成。
- R-LR-03：定义隐私政策/同意证据、DPA 与数据驻留核验的交接包和放行条件，不作法律结论，也不选择或绑定生产供应商。
- R-LR-04：输出顺序化实施计划、审阅门和回滚/停止条件；不改变已交付的 M1–M7 产品行为。

## Acceptance Criteria

- [x] AC-LR-01：每项上线阻断项均有来源、负责人角色、证据、验收人和状态，且没有以代码测试替代外部审查。
- [x] AC-LR-02：恢复、容量/SLO 与紧急访问都有合成环境演练步骤、预期证据、失败停止条件与生产前人工审批边界。
- [x] AC-LR-03：同意、隐私、DPA 和数据驻留的最小交接材料与缺口清单明确，未选供应商时不虚构结论。
- [x] AC-LR-04：规划明确后续可分开的实现任务及其依赖；生产部署、真实用户数据、密钥与供应商账户操作不在本任务内。

## Out of Scope

- M8 AI/语音、任何新产品功能或 M1–M7 范围扩展。
- 生产部署、供应商选择/签约、DPA 签署、法律或合规结论、真实用户数据/备份/密钥操作。
- 以测试通过声称已满足监管、合同或生产 SLO。

## Key Decision

- 本阶段只交付规划与合成环境演练设计；不实现新的上线准备工具或流程骨架。任何后续实现必须从本规划拆成独立任务并重新授权。

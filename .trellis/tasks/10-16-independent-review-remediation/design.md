# 整体整改设计

## 权威与边界

保持模块化单体。关系/用户/删除请求是授权来源；执行表为可变草稿/当前视图，fact_versions 为不可变完成/更正权威，settlements/point_ledger_entries 为账务权威。共享读取/写入资格函数封装冻结和成年策略，服务事务内复核；关系仍由 family-access 服务读取。

## 事务与并发

- 同主体资金变动和余额重建在读取流水前取得 users 行锁，保持主体→资源的一致顺序；更正在同事务新增事实、反向流水、新结算、审计和 outbox。
- 执行更新采用 expectedRevision；同键同载荷返回首次结果，异载荷冲突。命令结果与写入同事务，不用审计或 outbox 去重代替命令幂等。
- 普通完成检查提交时刻与次日22点；更正单独检查角色窗口。
- 修改已完成清单不篡改历史；新快照即使包含未完成子项也作为更正保存，取消不再满足的奖励；具体更正状态在实施记录说明。
- 个人计划只对新生成实例使用非零冻结规则；已有零分实例不能通过修改配置回写。

## 后台生命周期

沿用 outbox 租约/重试。周期扫描有限批量、至少一次执行，服务重查到期/状态。普通删除 now>=revocableUntil 且学生确认；安全强制独立原因/审计。待确认工作不反复制造为失败。

## 兼容与资源

仅追加 expand migration，编号分配为 0048 执行/更正、0049 身份、0050 有符号反向流水、0051 安全整数容量约束。主会话统一元账本，不改历史迁移。网络发送、扫描不在持有事务的临界区，有限超时。无外部配置明确不可用，生产拒绝开发绕过。

## 集成分工

schedule agent 负责 schedule/time-policy（除年龄）、相关 API/schema/migration0048与测试；security agent 负责身份/TOTP/验证码/subject资格、goals/manual points 门禁、migration0049与测试；lifecycle agent 负责 Worker/outbox/余额重建/ledger接口/删除导出/训练隐私和年龄、migration0050–0051与测试。主会话负责前端/client、CI/环境、规格/集成。均保留他人修改，不提交。

# 界面、目标与训练体验收敛

> 状态：已定稿，等待实施。

## Goal

在保留糖果/太空双主题和现有业务能力的前提下，统一全局页头、返回导航、计划编辑、计划日程、目标流转与训练结果的视觉和交互；同时把上一轮未在最终 SHA 上完成签署的关键回归门槛并入本轮，避免继续形成零散补丁链。

## Confirmed product decisions

- 本轮覆盖学生端与家长端的对应页面，同时验证桌面和手机布局。
- 日期时间移到全局页头右侧身份区，位于登录名称左侧；身份显示真实 `displayName`，缺失时依次回退账号和角色称呼，不再显示无意义的“我”。日期时间按固定 `Asia/Shanghai` 时区显示。
- 返回按钮与页面标题/操作区组成同一标题栏，不再单独占一行；触控区仍不小于 44px，并继续服从未保存离开保护。
- 计划编辑页取消悬浮保存栏，保存与取消作为表单末尾的普通操作区；取消“高级设置”折叠区，优先级进入基本信息。
- 计划级“开始日期”从编辑界面移除：新计划在内部使用创建当天，编辑已有计划时保留原值，不因隐藏字段被重写；单次计划项自己的执行日期仍保留。
- 日程生成仍由用户手动选择范围；开始日期和结束日期都允许选择当天，且结束日期不得早于开始日期。
- 计划日程重新设计月/周视图、日期单元、状态色、信息密度和详情弹窗；糖果/太空主题分别使用各自的配色语义，正文保持清晰对比度，弹窗不再使用造成模糊的缩放或滤镜效果。
- 学生对“进行中”目标提供“完成目标”操作；完成后等待负责家长评定。进行中、已完成/待评定、已评定等阶段使用可辨识但不只依赖颜色的卡片样式和状态标签。
- 家长评定继续保留“达成 / 未达成”两个结果；终态阶段统一显示“已评定”，同时明确展示具体评定结果，以延续现有积分、礼物、原因、审计和流水语义。
- 训练结果在会话完成后展示逐题“我的作答、正确答案、是否正确”，覆盖反应力、Stroop 和数字广度；学生本人及仍具有效授权的家长可见，原始事件负载不直接透传到前端，也不得写入日志、审计或错误信息。
- 训练结果页将免责声明作为标题右侧的小字；训练中心将两行使用说明放到标题右侧。窄屏时在同一标题区自然换行，不另占一张说明卡片。

## Requirements

### R01 全局页头身份与时间

- `PageShell` 接收明确的身份展示数据，不在组件内部硬编码用户称呼。
- 日期、星期和时间使用 `Asia/Shanghai`，客户端按分钟更新且不得产生 hydration 警告。
- 360px 宽度下允许日期信息紧凑换行或隐藏次要的时间精度，但真实姓名始终可辨认。

### R02 标题栏与返回导航

- 有返回入口的页面将返回按钮、标题、辅助说明和页面级操作放在一个响应式标题区。
- 返回行为、浏览器前进/后退和编辑页未保存拦截保持一致；不得通过新增一行或固定悬浮层规避布局。

### R03 计划编辑与日程生成

- 新建和编辑计划共用同一信息层级：基本信息（标题、说明、优先级）→ 计划项 → 普通操作区。
- 移除可见的计划级开始日期和“高级设置”文案；服务端契约中需要的开始日期由页面按上述确认规则提供。
- 保存、取消在桌面端右对齐，在手机端可纵向排列；滚动时不悬浮、不遮挡内容。
- 家长端和学生端的手动生成范围均允许从当天开始并在当天结束；已有绑定的生效边界仍是权威约束，若不能生成应给出明确原因，不得静默改写用户输入。

### R04 计划日程视觉重构

- 桌面月视图必须保证星期、日期、条目和状态层级清楚；日期不得因控件挤压发生逐字换行。
- 手机端使用适合窄屏的信息结构，可采用紧凑周条带 + 当日列表，禁止把桌面月表格机械压缩到 360px。
- 详情弹窗使用清晰字号、整数像素布局和主题表面色；支持键盘关闭、焦点约束及关闭后焦点恢复。
- 完成、待办、逾期等状态在糖果/太空主题中有协调的语义色，并同时提供文字/图标。

### R05 目标完成与家长评定

- 学生只能完成属于自己且处于进行中的目标；操作采用幂等键，重复点击或并发请求只产生一次状态迁移和一次审计/outbox 事实。
- 完成后学生不可再次完成，负责家长可评定；非负责家长、失效关系和越权主体均被服务层拒绝。
- 评定在数据库事务内更新状态，并与积分流水、审计和 outbox 保持原有原子性。
- 状态机固定为 `pending_approval → active → completed → succeeded | failed`；UI 依次显示“待批准”“进行中”“已完成 · 待评定”“已评定 · 达成 / 未达成”。
- 卡片至少区分待批准、进行中、已完成/待评定、已评定；终态仍保留评定人、评定时间、原因和奖励事实。

### R06 训练结果明细与标题说明

- 仅对已完成且事件校验通过的训练会话生成只读 review DTO；进行中的训练不得泄露答案。
- 反应力逐题展示刺激/期望动作、实际动作或未响应、正确性和反应时间。
- Stroop 逐题展示题面、正确颜色、用户选择和正确性。
- 数字广度逐题展示呈现序列、规则方向、正确答案、用户输入和正确性。
- 复用现有训练协议/校验器派生答案，不在页面复制评分规则；API 不返回无关原始事件字段。
- 学生结果页、家长授权结果页使用相同的明细组件和空态/异常态。

### R07 上一轮结转回归门槛

- 计划 definition、bindings 和 refresh-bindings 的写入意图保持分离，绑定事实不得被旧目标快照覆盖。
- 编辑页保存、启用、取消、浏览器前进/后退和未保存离开保护必须有确定性回归证据。
- 保持 DTO key、星期编码、弹窗焦点、训练运行中导航保护等上一轮已建立约束。
- 最终审核只接受与交接报告一致的固定提交 SHA；截图、命令输出和结论必须绑定该 SHA。

## Acceptance criteria

- [ ] AC01 学生与家长首页的全局页头在 1440、768、360 宽度下显示上海日期时间和真实登录名称，没有“我”。
- [ ] AC02 所有受影响的返回按钮与标题共处一个标题区，键盘、触控和未保存导航行为通过聚焦验证。
- [ ] AC03 新建/编辑计划不出现高级设置、计划级开始日期或悬浮保存框；优先级在基本信息，现有开始日期保存后不变。
- [ ] AC04 家长端与学生端都能选择“今天—今天”生成范围；非法倒序和不满足绑定生效边界的范围给出明确提示。
- [ ] AC05 月/周/手机日程在糖果与太空主题下通过视觉证据；日期不拥挤，状态可辨识，弹窗文字清晰且无焦点回归。
- [ ] AC06 学生完成进行中目标后进入已完成/待评定阶段，只有负责家长能评定；并发、幂等、越权和失效关系有服务层与数据库证据。
- [ ] AC07 各目标阶段的卡片色、标签和可用操作正确，且不只依赖颜色传达状态。
- [ ] AC08 三类训练的已完成会话都显示逐题作答与正确答案；进行中会话、越权家长和失效关系无法读取答案。
- [ ] AC09 训练标题说明在桌面端右对齐、360px 下在同一标题区换行，不再独占说明卡片。
- [ ] AC10 R07 的结转门槛在最终固定 SHA 上完成聚焦回归，实施报告中的 SHA、命令和浏览器证据一致。

## Out of scope

- 不改变训练题目生成、难度、计分算法或趋势口径。
- 不增加医学/智力判断、排行榜或家庭外比较。
- 不把手动日程生成改为自动生成。
- 不删除数据库/API 中作为历史事实存在的计划开始日期字段。
- 不进行与上述页面无关的全站组件重写。

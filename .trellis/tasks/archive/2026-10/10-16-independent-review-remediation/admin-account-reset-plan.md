# 管理员账号管理与强制改密：规划草案

2026-10-17 用户追加需求：管理员登录后能看到所有账号并重置密码，被重置账号下次登录必须自行设置新密码。

当前阶段：方案待用户最终确认。未修改本功能产品代码，未重置任何现有账号；之前的本地密码维护不作为本功能实施或验收证据。

## 目标与范围

- 管理员导航增加账号管理，可分页查看所有账号的登录标识、显示名、角色、状态和是否待改密；支持按账号/姓名搜索及角色筛选。
- 重置前明确展示目标账号并二次确认。管理员看不到原密码和密码哈希。
- 重置立即使目标账号旧密码和旧会话失效，标记必须改密。
- 临时密码登录后，任何角色都进入统一改密页；改密前只允许读取自身登录状态、修改本人密码和退出，服务端拒绝其他受保护业务读写。
- 用户设置符合现有密码规则且不同于临时密码的新密码后，清除待改密标记并建立新会话，恢复其原有权限；未验证家长随后仍需验证联系方式。
- 保留角色、禁用、删除冻结、年龄和家庭关系等限制；重置密码不启用被禁用或已删除的账号，不解除其他访问限制。
- 管理员登录和重置操作继续要求有效TOTP保证；重置密码不会删除、泄露或绕过TOTP配置。
- 新建普通账号的规则和历史密码不自动改变；不批量重置现有账号，不实现账号删除/启停/角色变更或短信找回。

## 用户已确认的规则

1. 可重置学生、家长和其他管理员，禁止管理员从重置功能重置自己；管理员本人使用修改密码。
2. 系统随机生成临时密码，仅首次向操作管理员显示一次；不保存可回读明文，不回看原密码。
3. 所有被重置角色使用临时密码登录后，必须自行设置新密码才能使用业务功能。

## 已确认的代码事实

- `users.mustChangePassword` 和 `authorizationEpoch` 已存在，无需为强制改密标志重复建列。
- 学生已有首次改密页及写入限制；家长没有统一强制改密路径，管理员目前不支持本人改密。
- `requireAdminSession` 已验证角色和会话TOTP保证；其他会话辅助函数尚未统一执行待改密限制。
- `change-password.service.ts` 当前存在事务外校验和改密幂等重放后重建会话的路径。本功能必须在统一主体锁下重新核对会话、旧密码、纪元及重放，避免管理员重置与用户改密交错覆盖，或旧请求重放越过更新后的凭据。
- 当前管理员导航只有首页、邀请码、我的；增加账号入口即可复用既有导航和双主题，不需要另建后台框架。
- 密码策略是6–12位且同时包含大小写字母和数字。此前本地统一密码属于用户授权的一次性维护例外，不放宽产品密码策略。

## 技术边界与不变量

- 路由薄层，列表和重置在identity模块；账号列表明确DTO白名单，禁止返回哈希、TOTP配置、会话ID或其他私密业务内容。
- 列表只由满足TOTP和已完成自身改密的管理员访问，分页/搜索有界，返回不缓存。
- 重置与本人改密使用一致的用户锁顺序。管理员与目标不同则按稳定UUID顺序锁定，再检查管理员状态、会话纪元及TOTP保证和目标资格。
- 重置写密码哈希、待改密、授权纪元、会话撤销、审计及必要outbox在同一事务完成；凭据不进入审计、事件或持久命令结果。
- 重置请求携带幂等键及列表返回的目标版本；同命令不产生第二次重置，旧列表上的冲突命令拒绝并要求刷新。随机临时密码不为重放持久化明文；首次响应丢失时需明确重新重置，不能假称可回看。
- 已失效会话和待改密会话不能执行管理员重置。本人改密保留当前会话已有MFA保证，不凭角色自行赋予保证。
- 普通改密与强制改密都需验证当前密码；新密码不能等于当前临时密码。
- 设置新密码、撤销旧会话与创建唯一新会话必须遵守同一主体并发边界；旧的已完成改密命令不得在凭据再次变化后重建新会话。

## 验收矩阵

| 场景 | 必须可观察的结果 |
| --- | --- |
| 未登录/学生/家长请求列表或重置API | 拒绝，不返回账号数据 |
| 管理员缺TOTP或本人待改密 | 拒绝账号管理业务 |
| 分页、搜索和角色筛选 | 有界、稳定、DTO无凭据 |
| 重置成功 | 新凭据可校验、旧密码失效、旧会话撤销、待改密为true |
| 同键重放/异载荷/双端并发 | 至多一次生效；冲突不覆盖新凭据 |
| 临时密码登录并直调业务API | 仅登录状态/本人改密/退出允许，其他拒绝 |
| 学生/家长/管理员改密 | 按确认的角色范围验证；成功后原权限恢复，MFA不丢失 |
| 重置与本人改密并发 | 真实PostgreSQL交错验证，无凭据覆盖或过期会话恢复 |
| 被禁用、冻结、删除或成年账号 | 原有限制不被密码操作解除 |
| 双主题×桌面/360px | 账号定位/确认/临时凭据展示/强制改密流程可用，无横向溢出 |

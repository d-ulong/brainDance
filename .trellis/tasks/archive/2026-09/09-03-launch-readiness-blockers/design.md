# 上线前阻断项规划设计

## Boundary

本任务产出上线放行包的设计，不产生生产配置、供应商绑定、法律结论或业务代码。放行包将已有技术演练结果与必须由组织或供应商提供的证据分开，避免“本地通过”被误写为“可上线”。

## Evidence Model

每个门槛使用同一记录：`控制目标 → 权威来源 → 证据工件 → 责任角色 → 审核人 → 状态 → 停止条件`。

| 门槛 | 可复用技术基础 | 外部/人工证据 | 放行边界 |
| --- | --- | --- | --- |
| 同意与隐私 | `guardian_consents` 只追加、版本化留存 | 法律审查的政策文本、监护同意适配结论、运营留档抽查 | 未完成不得开放首位家长关联 |
| 数据驻留与 DPA | 环境隔离与敏感数据边界 | 供应商地域、DPA、分包方与删除/备份条款 | 未核验不得写生产架构结论 |
| 恢复 | `scripts/recovery-drill.mts`、tombstone/revocation-first canary | 指定恢复负责人、备份配置、季度演练记录与审批 | 未演练或 canary 失败不得上线 |
| 容量与 SLO | `scripts/capacity-synthetic.mts`、100 档实测 | staging 合成压测、监控/告警截图或导出、容量审核 | 1k/10k 未实测只能标 deferred |
| 紧急访问 | 架构约束：重认证、非申请人双人批准、精确范围、限时、审计 | 值班名单、审批记录模板、演练纪要 | 未形成审批/审计闭环不得启用该例外能力 |

## Operating Sequence

1. 建立证据台账，标记每项为 `not-started / collecting / reviewed / accepted / blocked`，并列出不接受的替代证据。
2. 在隔离合成环境复核恢复与容量脚本的运行前置条件、输出字段、停止条件与可复现实例；不重新声称生产结果。
3. 将同意、DPA、驻留与紧急访问提交给对应人工责任角色；技术团队只提供数据流、字段、审计和演练材料。
4. 只有所有阻断项均被明确接受，才创建独立的生产就绪/部署任务；任一 blocker 仍存在时停止，不以部分测试替代。

## Compatibility and Rollback

本任务只增加任务文档，无数据库、API、产品 UI 或运行时兼容性变化。若证据不足，状态回到 `blocked`；不回滚历史事实、tombstone、审计或已签署的 M1–M7。

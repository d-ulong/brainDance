# 日程任务类型与执行记录：技术设计

## 边界与权威数据

- 任务类型和普通任务的固定清单属于计划条目定义，随 `plan_versions.schedule_rule` 和 `schedule_items.plan_snapshot` 冻结。
- 每个日程实例的可变执行状态存入新增 `schedule_task_executions` 表：子任务、番茄钟状态、暂停次数和累计暂停时长都不修改计划快照。
- 完成时将执行快照并入完成事实值；对已完成项的受控编辑创建新的手动完成事实，原事实与原积分不覆盖。原积分先写反向流水，再按新事实和冻结规则结算。

## 类型与执行语义

- `normal`：家长定义可选完成标准和固定子任务。子任务必须全部完成。
- `homework`：学生第一次开始或完成前创建子学习任务。名称必填；难度、预估耗时可空。所有子任务必须完成。
- `exercise`：不调用外部系统；开始只记录时间和“分析尚未开放”，支持番茄钟或手动完成区间。
- 番茄钟以服务端时间记录开始、暂停和继续；暂停次数、累计暂停秒数和最终专注秒数持久化。

## 权限与窗口

- 学生只能写自己的日程，且已完成项仅在 `familyDate` 当天可编辑。
- 已关联家长可写学生日程，且已完成项可编辑至 `familyDate + 60` 日结束；家长个人日程按本人权限处理。
- 服务端在所有执行、完成和更正写入前复核角色、关系、冻结状态、窗口和状态。

## 兼容与迁移

- 采用 expand：新增表和新 JSON 字段；既有计划条目默认解释为 `normal`，无清单。
- 查询 DTO 对旧记录返回默认类型、空子任务和无番茄钟数据。
- 不修改历史事实、结算或流水。

# 日程任务类型与执行记录

## 目标

让计划中的每个任务拥有明确类型与相应的执行记录方式：普通任务支持常用项目和固定子任务清单，作业任务支持学生填写与计时子学习任务，运动任务为未来运动分析保留统一入口；已完成任务的受控编辑必须保持积分流水可追溯。

同时补齐家长学生模块的导航一致性：学生列表、目标、计划、家庭推送和兑换页面都使用同一页内工具栏承载二级页签，不再在页面顶部重复显示二级导航和返回/标题区。

## 已确认事实

- 家庭日期和结算时区固定为 `Asia/Shanghai`。
- 当前计划版本以 `scheduleRule` JSON 保存定义，生成的 `schedule_items` 保存 `planSnapshot`；完成事实写入 `fact_versions`，积分结算和流水不可原地改写。
- 当前普通完成只能在计划日次日 18:00 前提交；对既有事实的更正应创建新事实版本、反向流水和新结算。
- 当前 `StudentManagementTabs` 仍在目标、计划、家庭推送、兑换页通过 `PageShell.secondaryNavigation` 展示；学生列表页已改为工具栏内展示，造成不一致。
- 运动分析系统尚未开放；本次不得接入或模拟外部运动分析结果。
- 日常验证遵循用户新增规则：默认只做固定 diff、静态/类型/lint 等代码级验证；除非明确要求或核心风险无法静态确认，不做全量测试、全量 E2E、构建或浏览器回归。

## 范围

1. 统一家长学生模块全部二级页签的页面布局。
2. 在计划定义和生成的日程快照中支持 `普通任务`、`作业任务`、`运动任务`。
3. 普通任务：家长可从内置常见项目添加；可选完成标准和固定子任务清单；日视图显示完成标准；全部子任务完成前不得完成主任务。
4. 作业任务：学生首次开始或完成时可录入任意子学习任务（名称、难度、耗时分钟）；可逐项完成；可选开始/结束时间、时长或番茄钟；存在未完成子任务时主任务不可完成；日程卡显示已完成数/总数。
5. 运动任务：开始时呈现“运动分析暂未开放”状态，但仍记录开始时间；支持手动时间/时长完成和番茄钟；不接入运动分析服务或生成运动报告。
6. 已完成日程的编辑权限窗口，以及会改变积分时的可追溯重算（反向流水加新结算）。

## 不在范围内

- 真实运动分析系统、设备接入、运动报告算法或健康/医学评估。
- 新的跨家庭模板市场、排行榜或外部通知渠道。
- 对历史计划定义或原始积分流水的原地修改。

## 验收标准

- 家长学生模块五个页面均在内容工具栏显示同一套二级页签，且不重复显示一级标题/返回区。
- 每条计划任务和生成日程均可识别任务类型，历史日程保留生成时的类型与完成标准快照。
- 普通任务的固定子任务未全部完成时，完成操作在客户端和服务端都被拒绝。
- 作业任务的子学习任务能独立保存、完成，并记录可选难度、耗时和番茄钟暂停次数/总暂停时长；主任务只有在所有子任务完成时可完成。
- 运动任务不调用未开放的外部服务，但能记录开始和完成时间或时长。
- 编辑权限严格按确认后的学生与家长窗口执行；导致积分变化的编辑不覆盖既有事实或流水，而是形成可审计的更正和反向/新结算。
- 日程日视图和卡片分别展示普通任务完成标准、子任务进度和相应执行信息。

## 已确认决策

- 编辑窗口统一按日程的 `familyDate`（`Asia/Shanghai`）计算：学生截止当天 23:59；家长截止该日期后第 60 天 23:59。

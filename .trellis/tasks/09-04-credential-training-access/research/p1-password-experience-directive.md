# P1 执行指令：统一密码规则与凭据交互

## 本阶段目标

落实 PRD 的 `R-CTA-01`、`R-CTA-02`，并为 `R-CTA-04` 提供密码相关的聚焦证据。只处理密码规则和密码输入体验；家长训练、训练 schema、migration、积分、日程和趋势均不在本阶段范围内。

## 冻结的行为与 authority

1. 所有新的、由产品界面/API 写入的用户密码必须满足同一**服务端权威**规则：长度 6–12 位，且至少各含一个大写英文字母、一个小写英文字母和一个数字；特殊字符可选。`Abc123` 是最短有效示例。
2. 规则只在写入密码前校验；不得以旧密码不符合新规则为由阻止登录、验证当前密码、会话刷新或已有账户使用。
3. 注册家长、创建受控学生的初始密码、学生修改密码、家长修改密码均必须调用同一个身份模块校验入口；不得复制正则或只依赖前端/Zod。无效输入不得调用 `hashPassword` 或写入用户表。
4. 修改密码仍须验证当前密码，仍须拒绝与当前密码相同的新密码，仍须在密码更新、审计和授权纪元更新同一事务内完成，并使旧会话失效后创建当前会话的新 cookie。学生和家长只能修改自己的密码；管理员不在本阶段新增自助改密入口。
5. 密码确认只属于浏览器交互：前端在发送请求前阻止不一致的“新密码/确认密码”，请求 body 不新增确认字段，服务端不信任该确认逻辑。
6. 每一个本阶段新增或改造的密码输入（包括当前、新、确认及受控学生初始密码）使用一致、可访问的显示/隐藏按钮。切换不改变输入值、焦点或提交状态；按钮有随状态变化的可读 `aria-label`。不可使用纯图标而无文本替代。

## 允许修改的范围

- 身份模块、现有注册/改密/受控学生创建 API 的 DTO 与调用点。
- 注册页、学生强制改密页、家长自助改密入口/页面、受控学生创建页，以及一个可复用的密码输入 UI 组件。
- 与上述行为直接有关的集成测试、定向 Playwright 用例、P1 实施记录。

家长自助改密可沿用现有 `POST /api/auth/change-password`，但该 route 必须改为认证后的学生或家长均可调用；学生的 `mustChangePassword` 拦截和既有跳转语义不得放宽。家长入口放在现有家长信息架构中，避免新建无导航可达的孤立页面。

## 明确禁止

- 不修改任何 `training` schema、训练 service/route、训练 UI、积分、日程、关系授权、migration 或 worker。
- 不改变管理员创建/种子密码的环境变量契约，不将明文密码、邀请码或测试真实凭据写入文档、审计、错误响应或日志。
- 不改变旧会话、审计、幂等重放、账号锁定或联系验证语义；不得绕过现有 `mustChangePassword` 写操作门禁。
- 不改写 PRD/design/任务状态/签署；不顺手格式化或重构无关文件；不启动开发服务、Docker 或全量 E2E。

## 实施要求

1. 在 `src/modules/identity/` 建立单一、可单测的密码策略函数（命名按现有风格）。它应给调用方稳定的 `IdentityError(VALIDATION_ERROR)`，并给 UI/API 返回不泄露密码内容的规则说明。
2. 将 `registration.service.ts`、`create-controlled-student.service.ts`、`change-password.service.ts` 改为调用它。服务层是最终 authority；route 的 Zod 只做字符串/长度边界，不能成为策略副本。
3. 将现有家长注册、学生首次改密、受控学生创建密码输入更新为规则文案、确认输入和可访问显示/隐藏。新增家长自助改密入口与相同交互；改密请求只发送 `currentPassword`、`newPassword` 与既有幂等键。
4. 对成功和失败状态给出明确、中文、非敏感的反馈。确认不一致时禁止提交；服务端拒绝时保留用户已输入值，除非现有安全行为要求清理。
5. 沿用现有样式、`data-testid` 命名和 API 错误处理约定。新测试不得依赖实际本机邀请码或管理员密码。
6. 在 `research/` 下新增 P1 实施记录，逐项映射 R/AC、文件、验证命令和未执行项；不要修改任务 manifest 或 status。

## 必须覆盖的断言

- 策略接受 `Abc123` 与其他 6–12 位合规密码；分别拒绝长度不足、超过 12、缺任一大写/小写/数字的情况。
- 三个服务入口均证明无效密码在哈希/写入前失败；至少一个断言证明旧的长度大于 12 的新密码被拒绝。
- 父母与学生均只能对自身调用改密；错误当前密码、相同密码、幂等重放和会话失效/新 cookie 保留既有契约。
- 浏览器用例覆盖注册页和改密页的确认不一致阻止提交、眼睛切换的 `type`/可访问名称变化，以及有效短密码提交路径。桌面和移动视口各至少覆盖一个上述关键交互。

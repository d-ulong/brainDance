# 独立计划、条件积分与家庭推送

## Goal

按 docs/requirements.md v1.0 完整实现独立计划与家庭推送、多内容日程与条件积分，修复本机图片上传。用户已在需求确认和最终范围总结后授权“行动吧”。

## Requirements

- R-MEDIA-01：本机显式不扫描，仍验证、重编码与私有读取。
- R-PLAN-01/02：独立内容、复制、分配；学生多套绑定、同一时段仅一套启用，切换替换。
- R-SCHEDULE-01/R-REPEAT-01：自动 15 日，手动今天及未来最多 90 日；某天/每天/每周多星期/每月多日期，不存在日期跳过。
- R-ITEM-01/R-POINT-01：多内容项，最晚开始+耗时上限，5/3/2 档唯一计分，正/0/负，无总额上限；预设规则及历史不可改写，次日 18:00 未完成结算。
- R-PUSH-01：独立内容、草稿、显式一个/多个/全部有权学生；学生/日期/tag 筛选、作答隔离。
- R-PUSH-02：学生对同一推送可提交多次独立作答；作答不得被后一次提交覆盖。评论可引用同一学生、同一推送内的一次作答或一条评论，并在家长详情中完整展示。
- R-PLAN-03：同一学生可同时启用多套计划。计划带整数优先级；同一学生、同一精确执行时间冲突时，仅最高优先级日程可执行，低优先级日程保留为“被覆盖”事实而不删除。家长可按学生或按学生下的某计划生成日程。
- R-NAV-01：父母端顶层保留首页、学生、兑换和我的；“我的训练”迁入“我的”。学生二级页签仅保留学生列表、计划、推送；创建与关联从学生列表中的操作入口进入。学生卡提供家长只读日程入口。
- R-PUSH-03：推送库卡片在同页详情中完整展示每位学生的作答与评论，家长可直接评论或引用作答/评论；投递数可悬浮查看学生姓名，并可向未投递学生追加同一推送。
- R-DOC-01：持续维护需求、决策与真实进度。

## 2026-09-12 增量需求：家长工作台与作答公开

### 目标

让家长在不离开学生工作区的情况下查看日程、兑换与推送互动；学生可在明确、可预测的公开时间后查看同推送其他学生的作答与评论。

### 已确认规则

- 推送由家长在创建或编辑时设置 `answerDisclosureDays`。未设置时，学生之间立即可见作答与评论；设置 N 天时，以推送实际 `publishedAt` 起算，学生立即看到自己的作答和家长评论，其他学生的作答及其评论在满 N 天后公开。家长始终立即查看全部。
- 作答和评论必须显示作者姓名；未公开内容不得通过评论、引用摘要或计数侧信道泄露。
- 兑换在“学生”二级页签中展示左右工作台：左侧为按学生、日期、兑换项目筛选的兑换记录，右侧为可编辑兑换项目卡片及新增按钮。新增与变更均在 Modal 内完成。
- 家长查看学生日程可选日期并按日、周、月范围查看；该视图只读。
- 返回导航以来源工作区为准：二级页签与返回在同一行；退出仅保留在“我的”或最顶部全局位置。低频使用说明改为悬浮提示/点击气泡。
- 手写作答优先提供画布并将导出 PNG 走现有受权上传链路；不支持画布或导出失败时，灰显并展示“功能待开放”。
- 兑换项目属于创建家长的家庭共享配置，而不是某个学生的私有目录；该家长当前关联的学生均可查看和申请，月限次按学生分别计算。旧 `student_id` 只作为管理锚点兼容保留。
- 学生管理二级页签上方不再展示独立标题/说明块；返回按钮与二级页签同一行，退出按钮位于全局顶部。

### 验收

- 两个学生收到同一推送时：家长看到双方作答；学生只看到自己的内容，至公开时间后才看到对方作答及非家长评论；公开后作者与引用摘要正确显示。
- 兑换工作台不发生页面跳转即可新增、编辑、启停项目，并能按学生、日期和项目查看记录。
- 日程的日、周、月查询边界正确，所有家长读写与学生可见性仍由服务端授权。
- 所有新增错误走 ErrorDialog；说明不占用页面主体高度；360px 不产生水平滚动。

## 2026-09-12 增量需求：学生计划、日程与推送详情

- 评论必须稳定展示其回复或引用目标的作者与正文摘要；回复、编辑、删除操作同行展示，不能因页面重构退化成裸 ID 或丢失引用关系。
- 家长与学生推送详情使用统一的信息层级：推送正文、附件、接收/公开信息、作答时间线、评论讨论区，详情保持在当前工作台内。
- 学生日程不再占用顶级菜单；首页和“我的”均提供入口。日程按日、周、月切换，具备今天、前后翻页、日期标题、时间轴/周网格/月网格和任务状态内容。
- 学生可查看家长分配给自己的计划；可创建、编辑和启用自己拥有的计划，并可对任一当前绑定到自己的计划生成允许范围内的日程。服务端必须强制 studentId 等于当前学生，不能借此管理其他学生或编辑家长计划。

### 增量验收

- 评论引用投影有聚焦测试，学生详情实际显示“回复/引用 作者：摘要”，操作按钮单行排列。
- 推送详情在桌面与 360px 下层级清晰且无横向滚动。
- 学生日/周/月日程正确计算查询边界和翻页范围；顶级菜单不含日程，首页及“我的”均能到达。
- 学生创建计划后可启用到本人、生成本人日程；家长计划只读但学生可为本人补生成，跨学生和编辑他人计划被服务端拒绝。

## 2026-09-12 增量需求：执行补录、日程清理与互动体验

- 已开始任务必须呈现清晰的“进行中”状态。学生也可从待完成任务直接完成，在确认框内填写开始时间，并填写结束时间或完成时长；服务端校验执行区间并按同一不可变积分规则自动结算。
- 增加按日期范围清理未来日程：仅允许今天起、连续不超过 90 天；家长可清理有权学生的待完成日程，学生只可清理本人自有计划生成的待完成日程；进行中、已完成及其他终态均保留。
- 兑换申请提交前必须展示项目、所需积分及当前余额确认；余额不足时客户端即时提醒且服务端再次拒绝。取消、删除、停用等同类不可逆或高影响操作统一确认。
- 月视图每个自然日固定为一个紧凑格，任务采用单行摘要并在超量时显示剩余数量。
- 推送库使用统一卡片与同页详情弹框；正文采用浅色高可读样式，图片先显示缩略图，点击后支持鼠标滚轮/拖动及触控缩放查看。
- 作答与评论使用统一社交信息流：明确作者、时间、引用目标及层级；回复、编辑、删除同行，不再把引用关系拆成无关卡片。

### 增量验收

- 开始后重新查询返回 `in_progress`；直接完成的实际开始/结束事实、积分档位与幂等重放均有聚焦测试。
- 清理命令的角色范围、日期上限、进行中/完成保留和重复请求均由服务端测试证明。
- 余额不足无法创建兑换申请；正常申请需二次确认，相关错误统一进入最上层 ErrorDialog。
- 推送卡片、详情、图片查看器和讨论层级在桌面与窄屏均可用；详情不发生页面跳转。

## 2026-09-13 增量需求：目标、角色自用计划与计划日程工作台

### 已确认的用户结果

- 所有家长推送入口统一使用当前页面内的详情弹框；详情直接展示推送正文、全部有权作答与评论，家长可在弹框内评论和引用，不再进入独立详情路由。
- 在家长“学生”工作台中增加与“计划”“推送”同级的“目标”页签。家长可为一名或多名当前关联学生创建直接生效的目标，字段包括内容、完成日期、期望积分、期望礼物和备注。
- 学生可提交期望目标；审批前为待审批提案，家长批准后才转为正式目标并同步生效。正式目标对相关学生与有权家长同步可见；只有家长能够评定成功或失败，并确认最终积分与礼物。
- 家长可以为自己制定目标和个人计划、生成并查看自己的日程；个人执行事实与学生资源隔离。
- 日、周、月日程均显示“本期已得分 / 本期全部完成最高可得分”。最高可得分按该范围内可执行正式日程冻结积分规则的最高结果聚合；取消、被覆盖和个人不计分计划不计入分母。
- 多处“我的今日概览”统计数字改为可交互摘要，点击或键盘触发后以浮层展示构成明细，鼠标悬浮可作为桌面端补充，不以 hover 作为唯一入口。
- 学生顶级“积分”入口改为“计划日程”，统一到一个工作台：顶部为“我的今日概览”，提供“制定计划”“最近目标”和“计划/日程切换”；日程与计划的其他入口全部归一到该页面。“积分余额、兑换项目和记录”迁入“我的”。

### 必须保持的边界

- 学生不能批准、评定或给自己发积分；目标积分必须进入不可变积分流水和余额投影，重试不能重复记账。
- 家长自用目标、计划和日程不能借用学生身份或进入学生积分余额；失效家庭关系必须实时阻断对学生目标的新写入。
- 多学生目标必须保存一份可复用目标定义及逐学生分配/状态事实，不能用逗号 ID 或共享一个学生状态代替。
- 本轮不新增实物库存、物流、支付或礼物自动兑换。手动惩罚扣分仅允许按已批准的独立入口、余额门禁和不可变流水执行，不能隐式绑定到目标失败。

### 已确认产品口径

- 已确认：正式目标由创建或批准学生提案的家长成为责任家长；只有责任家长可编辑、评定及发放奖励，其他关联家长只读。期望积分与礼物可同时填写，最终积分和礼物分别确认；偏离期望须记录原因。目标积分仅为非负奖励，失败默认 0；积分写入不可变流水，礼物只记录兑现状态且不折算积分。家长自用目标、计划和日程仅记录执行，不参与学生积分或礼物结算。
- 已确认：任一当前有效关联家长可执行独立的手动惩罚扣分；原因 2–200 字、分值为不超过当前余额的正整数，提交前二次确认。流水永久记录操作者、原因、时间和负分；学生及当前关联家长可见。原扣分家长只能通过填写原因的全额反向流水纠错，不能编辑、删除或部分撤销。扣分和撤销进入日/周/月积分净变动；目标失败仍默认为 0 分，不隐式扣分。

### v2.5 验收

- 家长推送库及按学生入口点击卡片均只打开同页详情弹框；家长能在弹框中评论、回复和引用，错误始终显示在最高层。
- 家长能把同一目标分配给多名学生，每个学生拥有独立状态；学生提案在批准前不生效，批准家长成为责任家长；非责任家长不能评定或发奖。
- 成功/失败评定只提交一次；目标积分最多产生一条奖励流水，礼物有独立兑现事实；相同幂等键重放不重复，异载荷冲突。
- 手动扣分不能造成负余额；并发扣分也不能越过余额。原操作者全额撤销后余额恢复，第二次撤销不重复入账；其他家长不能撤销。
- 日/周/月返回实际计划得分、目标奖励、手动扣分、净变动和可执行日程最高分；取消、被覆盖、个人计划不进入最高分。
- 家长自用目标、计划和日程可创建、生成及查看，且没有学生积分流水；学生不能访问家长个人执行数据。
- 学生“计划日程”顶级工作台包含今日概览、最近目标、制定计划和计划/日程切换；原计划和日程入口统一落入该页，积分与兑换从“我的”进入。
- 今日概览数字可用点击、键盘和桌面 hover 查看明细；360px 页面不横向溢出。

## 2026-09-13 增量需求：上下文防误操作、媒体与目标维护

- 家长进入某一学生的计划、推送、日程、训练、兑换、导出或复盘内容时，必须持续显示学生姓名，不以裸 ID 作为主要标识。
- 家长计划库增加与推送库一致的紧凑查询区，可按关键词、学生和绑定状态筛选；移除占位式“筛选”标题并保证宽窄屏对齐。
- 推送正文附件只出现在推送内容区，不得复制进每个学生互动卡片。已作答学生须有文字加视觉状态；作答与评论分区清晰。
- 推送创建和编辑均允许 0–5 张图片；服务端、客户端和内容规范化采用同一上限。受支持的视频链接展示为可播放卡片，点击后播放；未知链接仍为安全外链。
- 家长个人计划必须可创建、绑定本人、生成个人日程并在“我的”进入；个人目标同样从“我的”进入。
- 未评定目标允许有权责任人编辑核心内容；学生自提且待审批时允许提案学生编辑。任一同定义实例评定后核心内容冻结，责任家长可继续追加说明，历史说明不可覆盖或删除。

### v2.6 验收

- 学生上下文在所有家长单学生页面可见；计划与推送筛选布局在 360px 无横向溢出。
- 推送详情只有一个附件区，0/1/5 张图片均可保存，6 张被客户端和服务端一致拒绝；视频 URL 分类有聚焦测试。
- 已作答/未作答和“作答记录/评论讨论”不能仅凭颜色区分。
- 家长个人计划服务测试覆盖创建、自绑定、生成和零积分；目标编辑、终态冻结、评定后追加说明、权限和幂等均有隔离库测试。

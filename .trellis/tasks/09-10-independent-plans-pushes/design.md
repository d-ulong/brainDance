# 实施设计

## 约束

用户已批准 docs/requirements.md v1.0 全部范围并要求直接实现。一个任务集中交付，不新增 P 阶段，不覆盖现有未提交 UI/账号工作，不提交/push，不重置业务库。新增数据库契约先在隔离库验证；业务库迁移需备份、兼容检查。

## 所有权与事实

- 可复用计划内容由创建家长拥有，版本不可变；绑定属于学生与计划之间的应用关系。学生可同时启用多套计划；优先级由计划定义保存并快照到日程。绑定/生成锁学生与同刻日程集合，事务提交绑定/版本/日程/覆盖投影/审计/outbox。
- 保留现有 plans/versions/schedule_items/fact_versions/settlements/ledger 作为历史执行权威。新增内容库关联到学生执行计划，生成的任务携带完整内容项/积分/绑定版本快照。不得用页面隐藏代替服务端单启用约束。
- 复制仅复制配置，不复制分配和执行；默认次日生效、可选今天。多计划并行不再取消其他已绑定计划；解除绑定时只取消该计划未开始部分，已开始/完成和流水保留。
- 生成日期 = 请求窗口 ∩ 绑定/计划/内容项有效期 ∩ 重复规则。自动 D..D+14，手动含首尾最大 90 日、不能过去；周/月多选、短月跳过；幂等标识含学生执行计划、内容项和日期。
- 条件积分由不可变任务快照选择唯一档位；实际开始、完成及耗时事实由服务器记录，次日 18:00 决定未完成；更正沿用版本/反向流水。新规则不再叠加旧 +10，不能任意重写余额；零分也保留可解释结算。负分非自由罚分。
- 推送内容库与学生接收投递分离；已有学生推送/作答继续作为逐接收人事实，公开入口只聚合有权记录。内容可空接收草稿，发布复制接收快照；图片引用必须逐接收人授权，不能删除 studentId 校验达成复用。
- 每次作答是独立的 `push_answers` 事实，版本仅用于该次作答的编辑历史，不能再以 `push_id` 唯一 upsert。评论的引用目标为 nullable typed reference（answer/comment）；服务端验证目标与推送、学生一致，DTO 返回被引用摘要。
- 同刻冲突通过 `schedule_items.suppressed_by_schedule_item_id` 表示：低优先级 pending 项被保留但不可开始/完成；优先级相同以更早创建的计划胜出。生成或解绑后重新计算受影响学生、日期、时刻的 pending 集合；已开始/完成/结算项不改写。
- 学生详情是家长操作聚合根：`概览 / 计划 / 推送 / 关联` 为二级页签。推送详情在同页加载全部作答及评论，避免额外跳转。
- 媒体仅 local pilot + loopback + 非 production 显式允许不扫描；仍实际解码/重编码、大小限制、私有存储与授权，不能伪称恶意扫描通过。

## 失败/并发/生命周期

所有写入校验 idempotency key 与规范化载荷；同 key 异载荷冲突。两个家长并发绑定/生成锁同学生；同刻覆盖按优先级和稳定 tie-break 计算；重叠生成同一 occurrence 不重复；完成/未完成结算锁同任务，最多一个有效结果。文件解码和外部 I/O 不占数据库事务；原媒体连接锁/清理机制保留。

学生冻结/成年/失去关系实时阻断新写入；独立内容不授予家庭范围访问权。需要扩展的数据删除、导出、解除关系和未完成 worker 链路列为集成验收，不可遗漏。

## 验证

新增纯日期/计分矩阵单测；真实 PostgreSQL 绑定/并发/事务/约束测试；HTTP 权限与 DTO；手机/桌面关键流程。测试只在独立库串行运行。按风险补一次 typecheck 和变更文件 lint，不运行全量构建/测试。

## 2026-09-12 增量设计

- `family_pushes` 保存可空 `answer_disclosure_days`，公开时刻由 `published_at + interval` 计算；作答/评论读取 DTO 附带作者公开显示名和当前 actor 的 `visible` 判定。家长不受延迟限制；学生查询仅返回自己内容、家长评论及已公开的其他学生内容。引用目标也按相同判定过滤，不能返回隐藏正文或 ID。
- 推送内容库将公开天数作为内容版本字段，在发布时快照到各学生投递；追加接收人沿用当前版本的公开规则。迁移只 expand 新列并回填 null，旧推送保持立即公开。
- 兑换聚合页复用每学生目录/记录服务，但由一个聚合 API 返回授权后的目录、记录和学生显示名，避免 N+1 浏览器请求；写操作保留学生资源边界，Modal 调用既有写 API 并刷新聚合投影。
- 日程范围、返回层级和说明气泡均为前端组合：不新增日程权威表或绕过现有 API。手写画布在客户端导出 Blob，经现有图片验证/重编码/逐学生授权上传。
- 兑换项目读取 authority 为“项目创建家长与读取学生存在当前有效关系”，不再以项目历史 `student_id` 等值作为学生可见性条件。申请写入使用同一 authority 实时复核；项目月限次锁与计数键为 `(student_id, catalog_item_id, request_month)`。家长管理查询仍按历史管理锚点返回一次，避免共享项目在聚合页重复。
- `PageShell` 接收二级导航槽位并统一渲染“页签 + 返回”；启用该槽位的学生管理页以隐藏语义标题替代可见标题区，退出操作统一放在 masthead。
- 评论展示不再由页面各自拼接 ID：共享引用投影以 `parentCommentId / quotedCommentId / quotedAnswerId` 解析可见作者与摘要，家长和学生详情复用同一组件。
- 日程展示抽为纯前端 Calendar workspace，范围计算以 `Asia/Shanghai` 家庭日期为输入，日视图用时间轴、周视图用七列时间网格、月视图用六行日期格；移动端允许日历容器内部滚动但页面本身不得横向溢出。
- 计划库 actor 扩展为已验证家长或可写学生。学生仅能创建/编辑 ownerId 为自己的计划；启用只能绑定本人；生成允许 owner 本人或“当前绑定学生本人”，日程 ownerId 保留计划原所有者，审计 actorId 记录实际发起学生。
- “进行中”是由待完成日程的不可变开始事实/执行规则投影出的有效状态，不新增可漂移的终态枚举。直接完成接收显式执行区间，完成时刻是事实发生时间，提交时刻另行记录；时长积分仍由既有版本快照计算。
- 清理采用软取消而非删除：事务内锁定学生范围，且只更新 `pending`、未开始的日程。学生权限进一步限定 `schedule_items.owner_id = actorId`；家长须实时拥有该学生关系。日期窗口固定为 `[today, today+89]` 内。
- 兑换余额检查是创建申请事务内的服务端门禁；客户端余额仅用于尽早反馈，不能替代权威检查。高影响 UI 复用统一确认对话框。
- 推送详情和讨论区抽成共享展示层；评论树由 `parentCommentId` 建层级，answer/comment quote 以授权后的引用投影显示。媒体查看器只消费受权私有 URL，并将缩放/平移限制在客户端。

## 2026-09-13 v2.5 增量设计

- 目标采用“定义 + 逐主体实例 + 不可变命令/事件”模型。家长创建的定义可一次分配给多名学生；学生提案只创建本人待审批实例，首位批准家长写入责任家长。实例状态为 `pending_approval / active / succeeded / failed`，评定为单向终态；责任家长是正式目标唯一配置与评定 authority。
- 目标期望积分/礼物属于定义，实际积分/礼物属于评定事实。实际积分为非负整数并以 `goal_reward` 流水入账；礼物单独保存文字与兑现状态，不折算积分。家长个人目标沿用目标实例但 `subjectId = responsibleParentId`，服务端强制实际积分和礼物为空。
- 手动惩罚以独立 `manual_point_adjustments` 命令事实拥有扣分与全额撤销。事务先锁学生及余额投影，负数金额不得超过余额；撤销引用原扣分并只允许原操作者，新增正向 `manual_penalty_reversal` 流水。两类流水均与审计/outbox 同事务提交。
- 积分期间投影按 `Asia/Shanghai` 业务日期聚合：日程结算按 settlement period，目标奖励和手动调整按事实发生时间；输出分类金额与净变动。日程最高分从范围内未取消、未覆盖、可计分任务冻结的内容规则取每项最高正向结果求和，个人计划为零且不计入。
- 家长个人计划复用计划库，但自绑定时执行主体为本人并将冻结积分配置归零；关系校验替换为显式的“本人或有效关联学生”authority。家长个人日程只读展示，不能借此产生学生积分。
- 学生计划与日程组合为一个页面级工作台，共享一次会话和今日概览；旧 `/student/schedule` 仅兼容重定向到 `/student/plans?view=schedule`。顶级导航只保留一个“计划日程”入口，兑换及积分明细进入“我的”。
- 推送详情使用唯一共享 Modal 容器和 `PushDeliveryThread`，按学生旧列表跳转到带筛选的推送库，不再维护第二套详情页面行为。
- 所有新增写请求必须有 Idempotency-Key；Zod 只在 Route 边界验证，服务负责 authority、状态机、余额锁和跨表不变量；错误统一经 `toRouteErrorResponse` 映射并由最高层 `ErrorDialog` 展示。

### 数据流与回滚

- Migration 只 expand：新增目标、命令和手动调整表，扩展积分流水 source check；不重写旧目标、日程、结算或流水。
- 若界面回滚，新表和新 source type 保留可读；若服务回滚，既有流水仍可重建余额。试点库应用迁移前先做兼容检查，测试只指向隔离库。

## 2026-09-13 v2.6 增量设计

- 单学生上下文由共享只读展示组件消费当前授权学生列表并投影显示名；路由 ID 只用于查询，不作为用户主要识别信息。列表页被学生筛选锁定时也展示同一上下文。
- 计划/推送筛选只改变客户端已授权列表投影，不扩大服务端可见范围。筛选表单使用自适应网格与显式字段标签，不设置独立标题列。
- 推送正文媒体提升到详情 Modal 的内容层，只读取一个有权投递版本；逐学生组件仅负责该学生的作答与评论。图片数量权威上限为 5，Route 与领域内容规范化双重校验。
- 视频嵌入只接受明确白名单或直链格式；未知 URL 不进入 iframe。播放器在用户点击后加载，避免自动执行第三方内容。
- 目标核心编辑采用定义 revision 乐观并发。共享定义只有在全部分配均未终态时可改；终态后的补充说明写入 append-only `goal_notes`，不修改评定事实。写入、命令、审计与 outbox 同一事务。
- 家长个人计划不建立家庭关系；authority 是 `ownerId === subjectId === actorId`。生成的计划版本积分归零，隔离于学生余额。

## 2026-09-14 v2.7 增量设计

- 计划说明继续是 `plan_definition` JSON 的可选字段，使用既有 schema 与版本化计划定义，不新增可漂移的独立列或迁移；执行计划沿用既有 `plans.description` 投影。
- 当前上下文生成仅是前端主体选择收敛，服务端继续以计划绑定、owner 与实时关系为 authority，不能因隐藏选择器放宽 `studentId` 校验。
- 日程 start/complete 路由允许已认证的学生或家长；学生只操作本人，家长须对目标学生有当前有效关系。服务在事务内再次复核家长关系：开始命令保留 audit/outbox 操作人，完成命令额外以 `schedule_events.actor_id` 和人工完成事实的 `fact_versions.submitted_by` 保留代办主体；积分仍只写学生现有 ledger/projection。
- PageShell 返回显式 `router.push`，避免落回浏览器文档导航；退出保持 `window.location.assign` 以丢弃会话内页面状态。
